\section{What VASP-Flow does and where to find what}
\label{sec:start}
% ============================================================


VASP Workflow is a framework for setting up, running, and analysing DFT
calculations with VASP.  Two interfaces are provided:

\begin{itemize}
  \item \textbf{Browser GUI} (\texttt{vasp-gui.py}) --- a Flask web
        application: configure calculations through a form, run steps from
        the browser, view band-structure and DOS plots in real time.
  \item \textbf{CLI agents} (\texttt{vasp-agent.py} for workstations,
        \texttt{vasp-agent-slurm.py} for SLURM clusters) --- read POSCAR and a
        plain-text \texttt{instructions.txt} file and generate all INCAR,
        KPOINTS, POTCAR, and job scripts automatically.
\end{itemize}

Both interfaces share the same \texttt{modules/} back-end.

On a cluster, \cmd{vasp_diagnose.py} and the scripts in \cmd{ht_tools/} check finished runs, say why a step failed, write the repairs and resubmit them (Part~\ref{part:check}).

\subsection{Key features}

\begin{itemize}
  \item Functionals: PBEsol, PBE, R2SCAN, HSE06, RVV10, LDA, AM05
  \item Spin-orbit coupling (SOC) and collinear spin (ISPIN=2)
  \item Magnetic materials: correct MAGMOM per atom; spin-resolved band
        and DOS plots (spin-up / spin-down)
  \item GGA+U (Dudarev, LDAUTYPE=2) per element and orbital
  \item Automatic k-path detection via spglib
        (Setyawan--Curtarolo standard paths), with a geometric fallback
  \item Convergence testing: ENCUT and k-mesh sweeps
  \item DOS with orbital projections via \texttt{sumo}
  \item Phonons via phonopy, Wannier90 interface, DFPT Born charges
  \item LOBSTER bonding analysis (COHP/COBI/COOP) via the
        \texttt{08\_lobster} step
  \item Smart KPAR/NCORE auto-defaults scaled with MPI task count
  \item SLURM workflow with dependency-chained job submission
\end{itemize}

\section{Installing and configuring VASP-Flow}
\label{sec:install}
% ============================================================


\begin{lstlisting}[language=bash]
# 1. Clone the repository
git clone https://github.com/KeivanS/VASP-Flow.git
cd VASP-Flow

# 2. Install Python dependencies
pip install flask sumo

# 3. Optional: phonons and Wannier support
conda install -c conda-forge phonopy wannier90

# 4. First-time configuration (creates default_paths from template)
make setup
nano default_paths     # set VASP paths, POTCAR directory, MPI command
\end{lstlisting}

\subsection{default\_paths --- platform configuration}

The file \texttt{default\_paths} (Makefile key=value syntax) is read at
startup and its variables are exported as environment variables that the
GUI uses as initial defaults.  Settings saved via the GUI \emph{System
Setup} page take precedence; \texttt{default\_paths} acts as the
fallback for new installs or CLI-only use.

\begin{lstlisting}
PYTHON          = python3
VASP_STD        = /path/to/vasp_std
VASP_NCL        = /path/to/vasp_ncl
VASP_GAM        = /path/to/vasp_gam       # optional
VASP_POTCAR_DIR = /path/to/potpaw_PBE
MPI_LAUNCH      = mpirun -np              # or: srun
MPI_NP          = 16
WANNIER90_X     = wannier90.x
LOBSTER_X       = lobster                 # lobster binary or full path
VISUALIZER_X    = ~/bin/jmol             # Jmol, VESTA, OVITO, ...
\end{lstlisting}

\noindent\textbf{Three-layer configuration precedence} (highest wins):
\begin{enumerate}
  \item GUI System Setup page $\to$ saved to \texttt{settings.json};
        also auto-synced to \texttt{profiles/slurm.json} for SLURM agents.
  \item \texttt{default\_paths} $\to$ Makefile bootstrap, read on every
        \texttt{make run}.
  \item Built-in code defaults.
\end{enumerate}
\texttt{profiles/workstation.json} is used only when running
\texttt{vasp-agent.py~-{}-profile~workstation} directly from the
command line without the GUI.


\subsection{Configuring a cluster without the GUI}
\label{sec:remote-setup}

When running on a remote supercomputer where the browser GUI is not
available, executable paths and MPI settings must be configured
directly in \texttt{profiles/slurm.json} (for the SLURM agent) or
\texttt{profiles/workstation.json} (for the workstation agent).

\begin{lstlisting}[language=bash]
# On the cluster, after cloning VASP-Flow edit the file:
nano profiles/slurm.json 
# or
vi profiles/slurm.json 
\end{lstlisting}

The relevant keys (to be edited) are:

\begin{lstlisting}[basicstyle=\ttfamily\small]
{
  "vasp_std":   "/path/to/vasp_std",
  "vasp_ncl":   "/path/to/vasp_ncl",
  "vasp_gam":   "/path/to/vasp_gam",
  "wannier90_x": "wannier90.x",
  "lobster_x":  "/path/to/lobster",
  "mpi_cmd":    "srun",
  "mpi_np":     128,
  "modules":    ["intel/2023", "vasp/6.4"],
  "slurm": {
    "partition": "standard",
    "nodes":      2,
    "ntasks_per_node": 64,
    "time":       "12:00:00",
    "account":    "your-project"
  }
}
\end{lstlisting}

\noindent The \texttt{modules} list is prepended as \texttt{module load \ldots}
lines in every generated \texttt{run.sh}.  Alternatively, all path keys can be
set as environment variables in your \texttt{.bashrc}
(\texttt{VASP\_STD}, \texttt{LOBSTER\_X}, etc.)\ and the profile values left
as empty strings to inherit them.

\noindent\textbf{Note:} \texttt{profiles/slurm.json} is auto-regenerated
whenever you click \emph{Save Settings} in the GUI, so the authoritative
source for GUI users is the System Setup page.  On a headless cluster, edit
the JSON file directly and leave it in place.

\section{Running a calculation from the browser (GUI)}
\label{sec:gui}
% ============================================================

\subsection{Starting the GUI}

\begin{lstlisting}[language=bash]
make run          # launches on http://localhost:5001
\end{lstlisting}

\textbf{On a SLURM cluster} --- run on the login node, open on your
laptop via SSH port-forwarding:

\begin{lstlisting}[language=bash]
# On your laptop:
ssh -L 5001:localhost:5001 username@cluster

# On the cluster login node:
make run

# Open http://localhost:5001 in your laptop's browser
\end{lstlisting}

\subsection{Three-tab workflow}

\begin{enumerate}
  \item \textbf{Setup} --- configure the project, then click
        \emph{Generate Workflow}.
  \item \textbf{Workflow} --- run each calculation step; live VASP
        output streams to the browser.
  \item \textbf{Results} --- band-structure and DOS plots; OUTCAR analysis.
\end{enumerate}

To return to a previous project use the \emph{Select project} dropdown.
\textbf{$\to$ Workflow} jumps to the run tab; \textbf{Edit \&
Regenerate} re-opens Setup with all settings pre-filled.

Normal execution order: \textbf{relaxation $\to$ SCF $\to$ bands $\to$
DOS}.  Each step copies POSCAR/CHGCAR from the previous one automatically.
\end{notebox}

\subsection{Band structure options}

Leave the \emph{k-path} field blank to trigger \textbf{automatic
detection} from the POSCAR lattice vectors (Section~\ref{sec:kpath}).
Enter a path manually to override, e.g.\ \texttt{G-M-K-G}.

\subsection{DOS options}

Add projection rows to request orbital-resolved DOS:

\medskip
\noindent\hspace{1cm}Element: \texttt{Mo}\quad Orbitals: \textbf{d}
\hspace{1.5cm}
Element: \texttt{S}\quad Orbitals: \textbf{p}
\medskip

For spin-polarised calculations sumo plots spin-up positive and
spin-down mirrored below zero automatically.

\subsection{Workflow tab}

Each step shows three controls: \textbf{Run} (submit the step),
\textbf{Edit files} (open INCAR/KPOINTS/POSCAR in the browser; a
\texttt{.bak} is created on first edit), and a \textbf{status badge}.
\textbf{Run All Steps} chains every step and stops on failure.

\subsection{Viewing results of jobs run elsewhere}
\label{sec:open-results}

The GUI can show the results of calculations it did not set up or run ---
a finished cluster job, a whole high-throughput screen, or the small tarball
from \texttt{collect\_results.sh}.  On the bar under the tabs, type a path in
\textbf{Open results folder} and press \textbf{Open}:

\begin{tabularx}{\linewidth}{@{}lX@{}}
\thead
Path & What is opened \\ \midrule
one calculation, e.g.\ \texttt{\ldots/materials/mp-8} & that project (listed as \texttt{mp-8}) \\
a highthroughput folder, e.g.\ \texttt{\ldots/highthroughput\_test} & every
  \texttt{materials/<id>} (listed as \texttt{highthroughput\_test\textasciitilde mp-8}, \ldots) \\
an unpacked \texttt{screen\_results.tar.gz} (\texttt{\ldots/results}) & every
  \texttt{results/<id>} \\
\bottomrule
\end{tabularx}

The opened calculations are added to the project list (marked
\emph{opened}) and remembered in \texttt{settings.json}; \textbf{Results}
shows the selected one.  Plots that \texttt{analyze.sh} already wrote to
\texttt{analysis/} are shown as they are; any that are missing (because
\texttt{analyze.sh} never ran, or ran without matplotlib) are drawn by the GUI
from the raw outputs --- bands from \texttt{03\_bands/EIGENVAL}, COHP / COBI /
COOP and LOBSTER DOS from \texttt{08\_lobster/*.lobster}, ELF from
\texttt{02\_scf/ELFCAR} --- and saved into \texttt{analysis/}.  Nothing is
submitted or rerun.  A step counts as done when its OUTCAR shows VASP
finished (a relaxation must also reach the ionic criterion).
\textbf{Forget opened} removes them from the list without touching any file.

\texttt{collect\_results.sh} keeps this folder layout (\texttt{02\_scf},
\texttt{03\_bands}, \texttt{08\_lobster}, \texttt{analysis} per material)
with trimmed OUTCARs, so the tarball opens directly; set
\texttt{FULL\_OUTCAR=1} to keep the complete OUTCARs.

\section{Running a calculation from the command line}
\label{sec:agents}
% ============================================================

\subsection{On a workstation: \texttt{vasp-agent.py}}

The vasp agents read by default the POSCAR file and the instructions.txt file which contains 
the project name and type of calculation the user wants. 
It creates a folder by than name, from which the calculations must be launched.
Plots can be generated by running analyze.sh script from that folder.

\begin{lstlisting}[language=bash]
./vasp-agent.py
./vasp-agent.py -i my_inst.txt -s struct.vasp

cd ProjectName
./run_all.sh          # runs every step in sequence
./analyze.sh          # plots after all steps complete
\end{lstlisting}

\subsection{On a SLURM cluster: \texttt{vasp-agent-slurm.py}}

\begin{lstlisting}[language=bash]
./vasp-agent-slurm.py                  # uses profiles/slurm.json
./vasp-agent-slurm.py --profile slurm

cd ProjectName
./submit_all.sh        # sbatch with dependency chaining
squeue -u $USER        # monitor jobs
./analyze.sh           # run locally after jobs finish
\end{lstlisting}

Two-phase workflow when convergence tests are requested:

\begin{lstlisting}[language=bash]
./submit_convergence.sh     # STEP 1 -- submit convergence jobs
# review results to decide on what to set for ENCUT and KPOINTS, then:
./submit_calculations.sh    # STEP 2 -- prompts ENCUT/k-mesh, submits
\end{lstlisting}

\subsection{What the agent creates}

\begin{lstlisting}
ProjectName/
  instructions.txt
  POSCAR
  POTCAR               built once from $VASP_POTCAR_DIR
  01_relax/            INCAR  KPOINTS  POSCAR  POTCAR  run.sh
  02_scf/
  03_bands/
  04_dos/
  08_lobster/          if LOBSTER task selected (ISYM=0 NSCF + lobster)
  analysis/            plots generated by analyze.sh
  run_all.sh           workstation sequential runner
  submit_all.sh        SLURM job submission (dependency chained)
  analyze.sh           post-processing: plots + OUTCAR extraction
\end{lstlisting}

Without the GUI on a cluster, first set the VASP paths and SLURM defaults in \cmd{profiles/slurm.json} (Section~\ref{sec:remote-setup}).

\section{Describing the calculation: \texttt{instructions.txt}}
\label{sec:instructions}
% ============================================================

\subsection{An example to start from}

\begin{lstlisting}
Project: My material name

Methods: PBEsol functional
         collinear magnetization
         GGA+U with U=4.0 on Fe-d orbitals

Tasks: structure relaxation
       SCF calculation
       band structure
       DOS (projected on Fe-d and O-p)

Convergence: Test k-points 6x6x6 to 12x12x12
             ENCUT 400-600 eV

MAGMOM: 4.0
NSW: 100
EDIFFG: -0.01
MPI: 128
NODES: 2
NTASKS_PER_NODE: 64
WALLTIME: 12:00:00
\end{lstlisting}

The parser is case-insensitive and searches the entire file, so section
order is flexible.

\subsection{All keywords}
\label{sec:keywords}

\begin{tabularx}{\linewidth}{@{}lX@{}}
\thead
Keyword & Meaning \\ \midrule
\texttt{Project:} & Project name; becomes the output folder. \\
\texttt{MAGMOM:} & Initial magnetic moments in $\mu_{\mathrm{B}}$: one number
  for all atoms (\texttt{4.0}, \texttt{-3.0}), per element
  (\texttt{Fe=4.0, O=0.6}) or a per-atom list (\texttt{2*4.0 2*-4.0}).
  Any \texttt{MAGMOM} line switches spin polarisation on; default 2.0 when only
  ``collinear magnetization'' is given (Section~\ref{sec:magnetic}). \\
\texttt{ISIF:} & Relaxation type: 3=full, 2=ions only, 4=fixed volume. \\
\texttt{NSW:} & Max ionic steps. Default 100. \\
\texttt{EDIFFG:} & Force criterion in eV/\AA. Default $-0.01$. \\
\texttt{ENCUT:} & Manual plane-wave cutoff in eV. \\
\texttt{KMESH:} & Explicit Gamma k-mesh overriding the automatic density,
  e.g.\ \texttt{8 8 8} or \texttt{12} (cubic).  Applies to every automatic
  mesh (relax/SCF/DOS); for 2-D give the third value (\texttt{12 12 1}). \\
\texttt{KMESH\_DENSITY:} & Automatic k-mesh density tier: \texttt{coarse}
  (1000~kpra, default for relaxation and convergence tests) or \texttt{fine}
  (6000~kpra, default for SCF/DOS/spectroscopic steps).  kpra $= N_k \times
  N_\mathrm{atoms}$ where $N_k = N_x N_y N_z$; subdivisions scale as
  $N_i \propto |\mathbf{b}_i^*|$.  An integer is taken as the kpra target
  itself (also \texttt{KPRA:}, \texttt{KPOINTS\_DENSITY:}).  Overridden by
  explicit \texttt{KMESH} and by \texttt{KPOINTS} blocks. \\
\texttt{RELAX\_KMESH\_DENSITY:} & Density of the relaxation mesh
  (\texttt{coarse}, \texttt{fine} or an integer); default \texttt{coarse}
  whatever the SCF uses. \\
\texttt{PRESSURE:} & External pressure for constant-$P$ relaxation, e.g.\
  \texttt{10 GPa} or \texttt{50 kbar}.  Forces \texttt{ISIF=3},
  \texttt{IBRION=2}, \texttt{PSTRESS} (Section~\ref{sec:pressure}). \\
\texttt{INCAR: \ldots\ END\_INCAR} & Block of literal INCAR tags merged
  into the generated INCAR(s); optionally per-step
  (Section~\ref{sec:incar-raw}). \\
\texttt{NKPTS:} & k-points per band segment. Default 40. \\
\texttt{MPI:} & Total MPI tasks (nodes $\times$ cores/node). \\
\texttt{KPAR:} & Global k-point parallelisation. \\
\texttt{NCORE:} & Global cores-per-orbital. \\
\texttt{SCF\_KPAR:} \textit{etc.} &
  Per-step KPAR: also BANDS\_, DOS\_, RELAX\_, PHONONS\_
  (DFPT is forced to KPAR${}={}$NCORE${}={}$1). \\
\texttt{SCF\_NCORE:} \textit{etc.} & Per-step NCORE; same prefixes. \\
\texttt{NODES:} & Compute nodes (SLURM). \\
\texttt{NTASKS\_PER\_NODE:} & MPI tasks per node (SLURM). \\
\texttt{PARTITION:} & SLURM partition. \\
\texttt{WALLTIME:} & One time limit for every step, e.g.\ \texttt{12:00:00}
  (default: per step, Section~\ref{sec:slurm-time}). \\
\texttt{RELAX\_WALLTIME:} \textit{etc.} & Per-step time limit (RELAX, SCF,
  BANDS, DOS, WANNIER, DFPT, PHONONS, LOBSTER). \\
\texttt{ACCOUNT:} & SLURM account / allocation. \\
\texttt{DFPT\_EDIFF:} & EDIFF for DFPT. Default \texttt{1E-8}. \\
\texttt{PHONONS\_DIM:} & Supercell, e.g.\ \texttt{2 2 2}. \\
\texttt{PHONONS\_MESH:} & q-mesh, e.g.\ \texttt{20 20 20}. \\
\texttt{PHONONS\_DISP:} & Displacement in \AA. Default 0.01. \\
\texttt{PHONONS\_BAND:} & High-symmetry path for phonon bands. \\
\texttt{PHONONS\_NAC:} & \texttt{FALSE} to disable NAC. \\
\texttt{WANNIER\_NUM\_WANN:} & Number of Wannier functions. \\
\texttt{WANNIER\_PROJ:} & Projections, e.g.\ \texttt{Ga:s;As:p}. \\
\texttt{WANNIER\_EWIN:} & Energy window, e.g.\ \texttt{-5.0 to 15.0}. \\
\texttt{LOBSTER\_MAX\_KPTS:} & Largest $N_1N_2N_3$ of the symmetry-off LOBSTER mesh
  (default 10000, 0 = no limit). \\
\texttt{LOBSTER\_MAX\_KPW:} & Memory budget of the symmetry-off LOBSTER NSCF: largest
  k-points $\times$ plane waves; a denser mesh is reduced (default $6\times10^6$, 0 = no cap;
  Appendix~\ref{app:lobster-mem}). \\
\bottomrule
\end{tabularx}

\subsection{Functionals}

Methods: PBEsol functional    # recommended for solids
Methods: R2SCAN functional    # meta-GGA
Methods: HSE06 functional     # hybrid -- more accurate but slower
Methods: RVV10 functional     # van der Waals
\end{lstlisting}

Default ENCUT values: PBE 400~eV, PBEsol 450~eV, R2SCAN 680~eV,
HSE06 400~eV, RVV10 450~eV.

\subsection{Spin-orbit coupling}

\begin{lstlisting}
Methods: SOC with magnetization in z-direction
\end{lstlisting}

Uses \texttt{vasp\_ncl}.  Sets \texttt{LSORBIT}, \texttt{LNONCOLLINEAR},
and \texttt{SAXIS}.

\subsection{Magnetic materials (collinear spin)}
\label{sec:magnetic}

\begin{lstlisting}
Methods: collinear magnetization
MAGMOM: 4.0
\end{lstlisting}

Sets \texttt{ISPIN = 2} and \texttt{MAGMOM = N * value} in every INCAR,
where $N$ is the atom count from the POSCAR.  Three forms of the
\texttt{MAGMOM:} line are understood (any of them switches spin polarisation
on, with or without the words ``collinear magnetization''):

\begin{lstlisting}
MAGMOM: 4.0              # uniform; negative values keep their sign
MAGMOM: Fe=4.0, O=0.6    # per element (unlisted elements start at 0)
MAGMOM: 2*4.0 2*-4.0     # per atom in POSCAR order, n*value shorthand
\end{lstlisting}

A per-atom list must have exactly $N$ entries; the agent stops with an
explanatory message rather than silently falling back to a default.

\begin{tipbox}
Typical starting moments: Fe, Co $\approx$ 4--5~$\mu_{\mathrm{B}}$;
Ni $\approx$ 2~$\mu_{\mathrm{B}}$; Cr, Mn $\approx$ 3--4~$\mu_{\mathrm{B}}$;
rare earths $\approx$ 7~$\mu_{\mathrm{B}}$.
VASP converges the self-consistent value automatically.
\end{tipbox}

\textbf{Antiferromagnets} --- give the alternating signs directly, e.g.\
\texttt{MAGMOM: 4.0 -4.0 4.0 -4.0}.

\textbf{With SOC} (\texttt{Methods: SOC with magnetization in x-direction})
the moments are $3N$ components in the non-collinear \texttt{MAGMOM}; the
same \texttt{MAGMOM:} values are rotated onto the requested direction
(without this VASP would start every moment along its default $(1,1,1)$).
A list of exactly $3N$ numbers is used as the raw $x,y,z$ components.

\textbf{Spin-resolved plots} produced automatically after DOS/bands run:

\begin{itemize}
  \item \emph{Cumulative DOS} --- spin-up above the x-axis; spin-down
        mirrored below zero; elements colour-coded; solid = $\uparrow$,
        dashed = $\downarrow$.
  \item \emph{Band structure} --- spin-up in blue, spin-down in red
        dashed, same k-axis, $E_F = 0$.
  \item \emph{Projected DOS} --- sumo natively negates the spin-down
        channel in the orbital-resolved PDF.
\end{itemize}

Check the converged moment:
\begin{lstlisting}[language=bash]
grep "magnetization (x)" OUTCAR | tail -5
\end{lstlisting}

\subsection{GGA+U}
\label{sec:ggau}

\begin{lstlisting}
Methods: GGA+U with U=4.0 on Fe-d orbitals
         GGA+U with U=3.0 on Ni-d orbitals
         GGA+U with U=6.0 on Ce-f orbitals
\end{lstlisting}

Dudarev scheme (LDAUTYPE=2); $U_{\mathrm{eff}} = U - J$ with $J = 0$ set
automatically.  In the Dudarev formalism the parameter labelled $U$ is already
$U_{\mathrm{eff}}$, so no separate $J$ entry is needed.
Combine freely with \texttt{collinear magnetization}.

Default values come from \texttt{hubbard\_u\_defaults.csv} (repo root:
element, orbital, $U_{\mathrm{eff}} = U - J$, \ldots; 3d, 4d, 5d, 4f, 5f
elements) --- the only source of default values (there are no built-in
ones).  Dudarev's scheme uses $U_{\mathrm{eff}}$ only, so the INCAR gets
\texttt{LDAUU} $= U_{\mathrm{eff}}$ and \texttt{LDAUJ} $= 0$ (a J column in
the file is ignored); rows with $U_{\mathrm{eff}} = 0$ (Zn, Cd) get no
correction.  These values were fitted
for oxides, chalcogenides and halides, so their use is set by one optional flag in
\texttt{instructions.txt}:

\begin{tabularx}{\linewidth}{@{}lX@{}}
\thead
Flag & Effect \\ \midrule
(none) & \textbf{default}: GGA+U on the tabulated d/f elements only if the
  POSCAR contains a chalcogen or halogen (O, S, Se, Te, F, Cl, Br, I);
  otherwise $U = 0$. \\
\texttt{GGA\_U: ON} & tabulated $U_{\mathrm{eff}}$ on every tabulated element,
  whatever the compound. \\
\texttt{GGA\_U: OFF} & no U (also \texttt{no GGA+U}). \\
\texttt{GGA\_U: AUTO} & same as no flag. \\
\texttt{GGA+U with U=\ldots\ on El-orb} & explicit values; always win. \\
\bottomrule
\end{tabularx}

The key may also be written \texttt{GGA-U}, \texttt{GGA+U} or \texttt{GGAU},
and key and value are case-insensitive (\texttt{gga+u: on}); likewise the
command-line option of the high-throughput drivers accepts
\texttt{-{}-gga\_u}, \texttt{-{}-gga-u}, \texttt{-{}-gga+u} (or upper case)
with \texttt{auto}, \texttt{on}, \texttt{off} in any case.

The same U block is written to every step (relax, SCF, bands, DOS, LOBSTER,
\ldots), so all steps share one Hamiltonian.  Never automatic under
R2SCAN/HSE06.  All three routes honour the flag: the GUI (Setup,
\emph{Default Hubbard U}: auto / on / off), \texttt{vasp-agent.py} and
\texttt{vasp-agent-slurm.py}; the high-throughput drivers write it with
\texttt{-{}-gga\_u auto|on|off}.

\section{Choosing the k-point mesh}
\label{sec:kmesh}
% ============================================================

All Gamma-centred meshes are generated automatically from the POSCAR geometry.
Two density tiers are available via the \texttt{KMESH\_DENSITY} key
(Section~\ref{sec:keywords}):

\begin{tabularx}{\linewidth}{@{}lllX@{}}
\thead
Tier & kpra & Typical use & Notes \\ \midrule
\texttt{coarse} & 1000 & Relaxation, convergence tests & Agent k-point sweeps start here \\
\texttt{fine}   & 6000 & SCF, DOS, spectroscopic steps & Default for all production steps \\
\bottomrule
\end{tabularx}

Each axis gets a number of points proportional to its reciprocal-lattice length, so the spacing is the same in all directions; the formula is in Appendix~\ref{app:kmesh}.  The first line of each generated KPOINTS reports the mesh and the density reached.  Any integer may be given instead of \cmd{coarse}/\cmd{fine} (\cmd{KMESH_DENSITY: 3000}); the relaxation has its own density (\cmd{RELAX_KMESH_DENSITY}, default coarse).

\textbf{DOS mesh}: always $2N_x \times 2N_y \times 2N_z$ (the SCF ratios are
preserved; a 2-D slab keeps $N_z = 1$), for accurate spectral features.

\textbf{LOBSTER mesh}: the SCF mesh.  The LOBSTER NSCF runs with \texttt{ISYM}=0,
so it pays for every k-point of the mesh, not the irreducible wedge.  It is
therefore \textbf{kept within limits automatically}: if the mesh has more than
\cmd{LOBSTER_MAX_KPTS} points ($N_1N_2N_3$, default 10000, about 20$\times$20$\times$20)
or its k-points times plane waves exceed \cmd{LOBSTER_MAX_KPW} ($6\times10^6$, the
memory limit), it is reduced, keeping its ratios, until both hold; the KPOINTS
comment says so (Appendix~\ref{app:lobster-mem}).  The DFPT mesh is forced
to match the SCF mesh exactly.

An explicit \texttt{KMESH: N1 N2 N3} entry overrides the automatic density
for all steps, and a \texttt{KPOINTS} block (Section~\ref{sec:kpoints-block})
overrides everything for the step it names.

% ============================================================
\section{Setting INCAR and KPOINTS tags yourself}
\label{sec:incar}
% ============================================================

\textbf{Any VASP keyword can be specified explicitly} --- nothing is
hard-wired.  Three routes, in increasing precedence:
(1)~an \texttt{INCAR:} \ldots\ \texttt{END\_INCAR} block in the
instructions file (global or per-step);
(2)~the agents' \texttt{--incar} command-line option;
(3)~direct editing --- in the GUI every generated INCAR is editable per
step (Workflow tab $\to$ \emph{Edit files}, with an automatic
\texttt{.bak} backup), and of course the files on disk can be edited
before running.  This section covers the first two plus
\textbf{constant-pressure relaxation}.

\subsection{Raw INCAR passthrough}
\label{sec:incar-raw}

Place literal INCAR lines --- in ordinary VASP syntax --- inside an
\texttt{INCAR:} \ldots\ \texttt{END\_INCAR} block in your
\texttt{instructions.txt}.  They are merged into the generated INCAR(s):

\begin{lstlisting}
INCAR:                  # global block -- applies to every step
   LREAL  = Auto
   ALGO   = Fast
   NELMIN = 6
END_INCAR
\end{lstlisting}

A tag that the agent already writes is \textbf{overwritten in place}
(so \texttt{ALGO = Fast} above replaces the default \texttt{ALGO =
Normal}); any tag the agent does not normally emit is appended under a
clearly labelled \texttt{\# User INCAR overrides} section, so nothing is
silently lost.

To target a single step, name it on the header line.  Recognised steps
are \texttt{relax}, \texttt{scf}, \texttt{bands}, \texttt{dos},
\texttt{wannier}, \texttt{dfpt}, \texttt{phonons}, \texttt{lobster}:

\begin{lstlisting}
INCAR scf:              # applies only to 02_scf
   EDIFF = 1E-8
   SIGMA = 0.10
END_INCAR
\end{lstlisting}

\begin{notebox}
Precedence: a \emph{per-step} block beats the \emph{global} block, and
both beat the agent's generated defaults.  This is the recommended way to
set tags the parser has no dedicated keyword for (e.g.\ \texttt{LMAXMIX},
\texttt{ADDGRID}, \texttt{LVTOT}, \texttt{IVDW}, \texttt{AMIX}).
Full-line \texttt{\#} comments in the instructions file are ignored by
the parser, so a task keyword inside a comment does not enable that task.
\end{notebox}

\subsection{Explicit KPOINTS blocks}
\label{sec:kpoints-block}

The same block syntax writes a complete KPOINTS file, \emph{unchanged}, for
a step:

\begin{lstlisting}
KPOINTS scf:            # or KPOINTS_SCF:
   my SCF mesh          # first line = KPOINTS comment
   0
   Gamma
   9 9 5
   0 0 0
END_KPOINTS
\end{lstlisting}

Steps: \texttt{relax}, \texttt{scf}, \texttt{bands}, \texttt{dos},
\texttt{wannier}, \texttt{dfpt}, \texttt{phonons}, \texttt{lobster}; an
unnamed \texttt{KPOINTS:} block applies to every step except the band path.
Explicit blocks (INCAR and KPOINTS alike) \textbf{override every other
setting}: keywords, \texttt{KMESH}, the density tier and the automatic
\texttt{KPAR}/\texttt{NCORE}.  Steps derived from the SCF mesh --- DOS and
LOBSTER ($2\times$), DFPT and Wannier90 ($1\times$) --- follow an explicit
SCF block.  A marker file \texttt{.explicit\_kpoints} is left beside such a
KPOINTS so that the convergence phase-2 k-mesh patching never overwrites
it.  \texttt{KPAR} and \texttt{NCORE} written in an INCAR block also steer the
companion value (e.g.\ \texttt{KPAR = 2} on 16 ranks gives \texttt{NCORE = 2}).
In the GUI both block kinds are entered under
\emph{Setup $\to$ Advanced --- explicit INCAR / KPOINTS}.

\subsection{Command-line INCAR overrides (\texttt{--incar})}
\label{sec:incar-cli}

Both \texttt{vasp-agent.py} and \texttt{vasp-agent-slurm.py} accept a
repeatable \texttt{--incar} option that injects explicit VASP tags at
invocation time, without touching the instructions file:

\begin{lstlisting}[language=bash]
./vasp-agent.py -i instructions.txt -s POSCAR \
    --incar "ALGO=Fast; NELMIN=6" \      # every step
    --incar "scf:NBANDS=64"              # 02_scf only
\end{lstlisting}

Multiple tags in one option are separated by \texttt{;} (not commas ---
values such as \texttt{MAGMOM} may contain commas).  An optional step
prefix (\texttt{relax}/\texttt{scf}/\texttt{bands}/\texttt{dos}/%
\texttt{wannier}/\texttt{dfpt}/\texttt{phonons}/\texttt{lobster})
targets a single step.  Command-line tags are applied \emph{after} the
instructions-file blocks, so they win on conflicts.

\begin{notebox}
Exceptions: physics-critical guards are re-imposed regardless of
overrides --- \texttt{ISYM=2} and \texttt{KPAR=NCORE=1} in
\texttt{06\_dfpt}, and the symmetry-off \texttt{ISYM} in
\texttt{08\_lobster}.
\end{notebox}

\subsection{Constant-pressure relaxation}
\label{sec:pressure}

A single \texttt{PRESSURE} line turns the relaxation into a
constant-pressure optimisation: the agent forces \texttt{ISIF = 3} (cell
shape + volume + ions) and \texttt{IBRION = 2}, and imposes the target
pressure through \texttt{PSTRESS}.

\begin{lstlisting}
PRESSURE: 10 GPa        # also accepted: "5 kbar", "constant pressure 8"
\end{lstlisting}

VASP's \texttt{PSTRESS} tag is in \textbf{kBar} (1~GPa $=$ 10~kBar).  The
agent converts automatically; if no unit is given, \textbf{GPa is
assumed}.  The resulting \texttt{01\_relax/INCAR} reads, e.g.:

\begin{lstlisting}
# Constant-pressure relaxation @ 10 GPa  (PSTRESS = 100 kBar)
IBRION = 2
ISIF   = 3
NSW    = 100
EDIFFG = -0.01
PSTRESS = 100   ! external pressure in kBar (10 GPa)
\end{lstlisting}

\begin{tipbox}
\texttt{PSTRESS} adds the $PV$ term so the relaxed cell sits at the
requested external pressure.  Use a tight \texttt{EDIFFG} and a
well-converged \texttt{ENCUT}; the Pulay stress error grows at high
pressure, so verify with a higher \texttt{ENCUT} before trusting the
equilibrium volume.
\end{tipbox}

How the SCF starts from the relaxation (which files are copied, \cmd{ISTART}/\cmd{ICHARG}) is described in Appendix~\ref{sec:handoff}; which eigensolver each step uses in Appendix~\ref{app:algo}.

\subsection{ELF bond profiles}

If an SCF calculation writes an \texttt{ELFCAR} (electron localization
function, requested with \texttt{LELF = .TRUE.} --- the high-throughput
driver sets this automatically), the utility \texttt{elf\_bonds.py} plots ELF
along each non-equivalent nearest-neighbour bond, sampled from one atom centre
to the other:

\begin{lstlisting}[language=bash]
./elf_bonds.py [ELFCAR] [--out PREFIX] [--nn-scale 1.2] [--npoints 200]
\end{lstlisting}

It parses the \texttt{ELFCAR} grid directly (only numpy + matplotlib), groups
bonds by element pair and length (rounded to 0.01~\AA{}) to pick the
non-equivalent ones, and interpolates ELF along each bond with periodic
boundary conditions.  Output is \texttt{FORMULA\_elf\_bonds.png/pdf} (the prefix
defaults to the reduced formula, e.g.\ \texttt{MoSe2\_elf\_bonds.pdf}; override
with \texttt{--out}) showing ELF vs.\ distance along the bond, with the
ELF~$=0.5$ homogeneous-electron-gas reference marked.  \texttt{analyze.sh}
runs it automatically when \texttt{02\_scf/ELFCAR} is present, and the GUI
Results tab shows the same plot whenever the SCF wrote an \texttt{ELFCAR}.

\begin{tipbox}
Reading the profile: ELF is high (near~1) where electrons are paired and
localized.  A covalent bond therefore shows an ELF \emph{maximum} in the
bonding region \emph{between} the atoms (e.g.\ Si--Si $\approx 0.95$ at
mid-bond), not at the nuclei.  Because VASP builds the \texttt{ELFCAR} from the
pseudo (valence) density, the value \emph{at} an atom centre is a PAW artifact
--- often low, even $\approx 0$ for heavy atoms --- so read the bonding region,
not the endpoints.
\end{tipbox}

\begin{notebox}
VASP does \emph{not} compute ELF for non-collinear / spin-orbit runs
(\texttt{LSORBIT}/\texttt{LNONCOLLINEAR}); it prints
\texttt{"WARNING: ELF not implemented for non collinear case"} and writes an
all-zero \texttt{ELFCAR}.  \texttt{elf\_bonds.py} detects this and reports it
rather than producing a blank plot --- re-run the SCF \emph{without} SOC to get
ELF.
\end{notebox}

\paragraph{ELF without slowing down the SCF.}  \texttt{LELF} needs KPAR${}={}$1.  With \cmd{ELF: separate} (or \cmd{ELF: two-step}) in \cmd{instructions.txt} the SCF runs at full KPAR and a short KPAR${}={}$1 restart in \cmd{02_scf/elf/} writes the ELFCAR (Appendix~\ref{sec:elf-separate}); \cmd{ht-mp-scf.py} does this by default.

\section{Convergence tests for ENCUT and k-points}
\label{sec:conv}
% ============================================================

\begin{lstlisting}
# Range (auto-steps)
Convergence: Test k-points from 6x6x1 to 18x18x1    # 2D material
             Test k-points from 6x6x6 to 12x12x12   # 3D material
             ENCUT 400-600 eV

# Explicit mesh list

\end{lstlisting}

The \texttt{start:step:stop} form is the only one that sets the step; the

tests at all.

energy in \texttt{OUTCAR}.  \texttt{LWAVE}, \texttt{LCHARG}, \texttt{LORBIT}
and \texttt{LELF} are dropped, which avoids writing a full WAVECAR per point
and, because \texttt{LELF} pins KPAR to 1, restores k-point parallelism for
the sweep.

Results in \texttt{00\_convergence/kpoints/} and
\texttt{00\_convergence/encut/}.

\begin{lstlisting}[language=bash]
./run_convergence.sh          # workstation
./submit_convergence.sh       # SLURM
./analyze_convergence.sh      # plots: energy / pressure / forces
\end{lstlisting}

After the runs the smallest ENCUT and k-mesh that meet the force and stress criteria are written to \cmd{00_convergence/converged_params.txt} and offered as defaults for phase~2 (Appendix~\ref{app:conv}).

\subsection{KPAR and NCORE}

KPAR and NCORE are set automatically per step from the number of MPI ranks and the step's k-points (rule in Appendix~\ref{app:kpar}).  To set them yourself:

MPI: 128        KPAR: 4        NCORE: 8

# Per-step (take priority over globals)

SCF_NCORE: 8    BANDS_NCORE: 16   DOS_NCORE: 8
RELAX_KPAR: 2   PHONONS_KPAR: 1   # DFPT is always KPAR=1, NCORE=1
\end{lstlisting}

\subsection{Cluster defaults: \texttt{profiles/slurm.json}}

\subsection{Walltime per step}
\label{sec:slurm-time}

Each step is its own SLURM job with its own time limit, so short steps get
short limits (and better queue priority).  Defaults:

\begin{tabularx}{\linewidth}{@{}lX@{}}
\thead
Step & Walltime \\ \midrule
\texttt{01\_relax} & 08:00:00 \\
\texttt{02\_scf} & 04:00:00 \\
\texttt{03\_bands}, \texttt{04\_dos} & 02:00:00 \\
\texttt{08\_lobster} & 04:00:00 (symmetry-off NSCF over the full mesh, plus the
  LOBSTER projection) \\
others & the profile time \\
\bottomrule
\end{tabularx}

Priority: \texttt{<STEP>\_WALLTIME} $>$ \texttt{WALLTIME} $>$ these defaults
$>$ \texttt{profiles/slurm.json}.  In \texttt{ht-semimetals.py} directories
the same defaults sit in \texttt{env.sh} (\texttt{TIME\_RELAX} \ldots;
\texttt{retune.sh -{}-time-relax \ldots}); that is the only place to change
them --- the per-material \texttt{instructions.txt} carry no walltime.

A step that reaches its limit is stopped cleanly 15~minutes before and continued automatically in a requeued job (Appendix~\ref{sec:slurm-continue}).

\subsection{Born charges, dielectric and piezoelectric tensors (DFPT)}
\label{sec:dfpt}

The \texttt{DFPT} task creates \texttt{06\_dfpt}, which computes Born
effective charges $Z^{*}$, the macroscopic dielectric tensor, and the
piezoelectric stress tensor from the converged SCF charge density.

Two routes are generated automatically depending on the method:

\begin{tabularx}{\linewidth}{@{}lX@{}}
\thead
Method & Route \\ \midrule
PBE, PBEsol, LDA, AM05 (no SOC) &
  Linear response: \texttt{IBRION=8}, \texttt{LEPSILON=.TRUE.} \\
SOC, HSE06, or R2SCAN &
  Finite field (PEAD): \texttt{IBRION=6}, \texttt{LCALCEPS=.TRUE.}
  --- VASP's DFPT is not implemented for noncollinear magnetism,
  hybrids, or meta-GGAs.  Requires an insulating system. \\
\bottomrule
\end{tabularx}

KPAR, NCORE and ISYM are fixed for this step (Appendix~\ref{app:dfpt}).

\texttt{run.sh} executes \texttt{extract\_born.py} after VASP, which
writes:

\begin{itemize}
  \item \texttt{BORN} --- phonopy NAC format: electronic
        $\varepsilon_{\infty}$ + $Z^{*}$ per atom.
  \item \texttt{born\_charges.txt} --- human-readable summary shown in
        the GUI Results tab: electronic (ion-clamped)
        $\varepsilon_{\infty}$, ionic contribution, total static
        $\varepsilon_{0}=\varepsilon_{\infty}+\varepsilon_{\mathrm{ion}}$;
        $Z^{*}$ tensors labelled by element; an acoustic-sum-rule check
        ($\sum_{\mathrm{ions}} Z^{*}$ should vanish --- a large residual
        indicates an under-converged k-mesh or EDIFF); and the
        piezoelectric stress tensors $e$ (C/m$^2$, clamped-ion, ionic,
        and relaxed-ion total; meaningful only for non-centrosymmetric
        crystals).
\end{itemize}

\texttt{DFPT\_EDIFF} in \texttt{instructions.txt} tightens the
electronic convergence (default \texttt{1E-8}).

\subsubsection{Example}

\begin{lstlisting}
Project: GaAs
Methods: PBE functional
Tasks: relaxation, SCF, DFPT Born charges and dielectric
DFPT_EDIFF: 1E-8
MPI: 16
\end{lstlisting}

In the GUI, tick \textbf{Born Charges \& Dielectric Constant (DFPT)} on
the Setup tab (the DFPT EDIFF field is optional); after running
\texttt{06\_dfpt} from the Workflow tab, the full summary appears in
the \textbf{Born charges} panel of the Results tab.  With SOC, HSE06
or R2SCAN selected under Methods, the finite-field INCAR is generated
automatically --- no extra input is needed.  For LO-TO splitting in
phonon spectra, combine with the phonon task as in the GaAs worked
example (Section~\ref{sec:example-gaas-nac}).

\subsection{LOBSTER bonding analysis (COHP / COBI / COOP)}
\label{sec:lobster}

Adding \texttt{LOBSTER COHP/COBI analysis} (keywords: \texttt{lobster},
\texttt{cohp}, \texttt{cobi}, \texttt{coop}, \texttt{bonding}) to the
task list creates \texttt{08\_lobster}: a symmetry-off NSCF that reads
\texttt{02\_scf/CHGCAR}, followed by a run of the \texttt{lobster}
binary.

\begin{itemize}
  \item \textbf{ISYM=0 is required} --- a symmetrised k-mesh gives
        unusable COHP/ICOHP values (wrong sign, errors above 100\%).
        The generated INCAR sets it automatically.
        With SOC enabled, \textbf{ISYM=$-$1} is used instead: spin-orbit
        coupling breaks time-reversal symmetry, which ISYM=0 would still
        assume.
  \item The k-mesh is the SCF mesh, reduced automatically above 10000 points or when
        the symmetry-off run would not fit in memory (\cmd{LOBSTER_MAX_KPTS},
        \cmd{LOBSTER_MAX_KPW}, Appendix~\ref{app:lobster-mem}).
  \item \texttt{NBANDS} is auto-set to at least the LOBSTER
        basis-function count; \texttt{LMAXMIX} is chosen from the
        elements (6 for $f$, 4 for $d$, 2 for $sp$).
  \item The LOBSTER binary is set with \texttt{LOBSTER\_X} in
        \texttt{site.env} (default \texttt{lobster-5.1.0-OSX}); it can
        be overridden at runtime via \texttt{\$LOBSTER\_BIN}.
\end{itemize}

\begin{lstlisting}
Project: NaCl
Methods: PBE functional
Tasks: SCF, LOBSTER COHP/COBI analysis
MPI: 16
\end{lstlisting}

Run with \texttt{./vasp-agent.py} (builds and runs \texttt{02\_scf} +
\texttt{08\_lobster}); the GUI shows COHP/COBI/COOP plots on the
Results tab.  To aggregate averaged COHP/COBI over many projects into
\texttt{lobster\_acohp\_acobi.csv}, run
\texttt{python3 lobster\_postprocess.py}.

Why the LOBSTER projected DOS and the VASP DOS differ is explained in Appendix~\ref{app:lobster-dos}.

\subsection{Step by step on the cluster (Rivanna)}
\label{sec:ht-howto}

\textbf{1. Every new login}: update the code and set the environment.  The
drivers download from MP, so run them on the login node (internet access).

\begin{lstlisting}[language=bash]
cd ~/VASP-Flow && git pull
source ~/vaspenv/bin/activate    # python env (see below)
export MP_API_KEY=your_key       # materialsproject.org/api
export VASP_POTCAR_DIR=/path/to/PAW_PBE
\end{lstlisting}
First time only: \texttt{python3 -m venv \textasciitilde/vaspenv \&\&
source \textasciitilde/vaspenv/bin/activate \&\& pip install pymatgen mp-api
spglib numpy matplotlib}.

\textbf{2. Put the list in a file}, e.g.\ \texttt{\textasciitilde/VASP-Flow/lists/mylist.txt}.

\textbf{3a. Semimetal screen} (\texttt{ht-semimetals.py}):
\begin{lstlisting}[language=bash]
cd ~/VASP-Flow
python3 ./ht-semimetals.py --list lists/mylist.txt \
    --out highthroughput_mylist --api-key "$MP_API_KEY" \
    --kpra 8000 --single-node
cd highthroughput_mylist
vi env.sh                    # VASP module, LOBSTER_BIN, ANALYSIS_PYTHON
./retune.sh --time-lobster 06:00:00   # optional: change a step walltime
./submit_all.sh              # POTCARs + submit; re-run = resume
./status.sh                  # progress per step
# when finished:
./postprocess_all.sh         # -> screen_lobster_all.csv
./collect_results.sh         # -> screen_results.tar.gz
\end{lstlisting}

\textbf{3b. Relax + SCF + ELF} (\texttt{ht-mp-scf.py}).  It writes the
material folders into the directory it is run from, so use a work directory:
\begin{lstlisting}[language=bash]
mkdir -p /scratch/$USER/ht_mylist && cd /scratch/$USER/ht_mylist
python3 ~/VASP-Flow/ht-mp-scf.py -l ~/VASP-Flow/lists/mylist.txt \
    --agent slurm --no-chain --nodes 1 --ntasks-per-node 40 \
    --account elmgroup --kpra 8000 --encut 520
./runall.sh     # build inputs, submit relax -> SCF+ELF -> LOBSTER
squeue -u $USER
\end{lstlisting}
Check \texttt{\textasciitilde/VASP-Flow/profiles/slurm.json} first: its
\texttt{modules} list must load a working VASP on the cluster (on Rivanna
\texttt{vasp/5.4.4} alone; extra compiler/MPI modules cause version swaps).
Choose \texttt{-{}-encut} as about $1.3\times$ the largest ENMAX in the set
(the ISIF = 3 relaxation needs it against Pulay stress).
\texttt{-{}-no-chain} lets the materials run in parallel; the default
(chained) runs everything one after another, and one failed step then blocks
all later jobs.

\textbf{POSCARs already downloaded?}  Neither driver downloads a structure
it already has.  \texttt{ht-semimetals.py} reuses
\texttt{<out>/\_ht\_inputs/<id>/POSCAR}, \texttt{ht-mp-scf.py} the
\texttt{\_ht\_inputs/} of the current directory.  To take them from another
folder --- e.g.\ an older highthroughput directory --- add
\texttt{-{}-poscar-dir <folder>} (repeatable; it looks for
\texttt{<id>/POSCAR}, \texttt{materials/<id>/POSCAR},
\texttt{\_ht\_inputs/<id>/POSCAR} or \texttt{<id>.vasp}).  No MP key or
internet is needed then; only missing structures are downloaded.
\begin{lstlisting}[language=bash]
python3 ./ht-semimetals.py --list lists/mylist.txt --out highthroughput_new \
    --poscar-dir highthroughput_mylist --kpra 8000 --single-node
\end{lstlisting}

\textbf{4. Test first.}  Run two or three materials before a long list, then
read the timings and look at the plots (the per-step walltimes of
Section~\ref{sec:slurm-time} are defaults; steps that hit them continue
automatically):
\begin{lstlisting}[language=bash]
grep "Elapsed time" materials/*/0*/OUTCAR     # ht-semimetals
grep "Elapsed time" */0*/OUTCAR               # ht-mp-scf
\end{lstlisting}

\textbf{5. Look at the results} in the GUI (Section~\ref{sec:open-results}):
unpack \texttt{screen\_results.tar.gz} on your computer (or run the GUI on
the cluster with \texttt{ssh -L 5001:localhost:5001}) and use
\textbf{Open results folder}; missing plots are drawn there.

All options of the two drivers are listed in Appendix~\ref{app:ht}.  When the jobs have finished, check and repair the runs as described in Part~\ref{part:check}.

% ============================================================
\section{Finding and repairing failed runs (\texttt{vasp\_diagnose.py})}
\label{sec:diagnose}
% ============================================================

After a batch of VASP-Flow calculations --- one project or a few thousand
materials --- some runs will not have finished: a job ran out of memory or time,
an SCF did not converge, a band structure diverged, LOBSTER stopped, a
convergence test broke off.  \cmd{vasp_diagnose.py} finds these runs, tells you
why each one failed and writes, for each of them, a shell script that repairs
the inputs and resubmits exactly what has to be redone.  One more script
submits all of these repairs.

It checks the steps \cmd{00_convergence}, \cmd{01_relax}, \cmd{02_scf},
\cmd{03_bands}, \cmd{04_dos}, \cmd{06_dfpt} and \cmd{08_lobster}, for runs made
with \cmd{vasp-agent.py}, \cmd{vasp-agent-slurm.py} or the high-throughput
drivers.

\begin{tipbox}
Running \cmd{vasp_diagnose.py} never changes or submits anything.  It only
writes a report and scripts.  Your runs are touched only when you run those
scripts.
\end{tipbox}

\subsection{Quick start}
On the cluster, in your VASP-Flow folder, give it the list file you made the
runs from:

\begin{lstlisting}[language=bash]
cd ~/VASP-Flow
python3 vasp_diagnose.py my_list.txt --out diag_round1   # 1. diagnose (read-only)
bash ht_tools/show_problems.sh diag_round1               # 2. what failed, what will change
nohup bash diag_round1/submit_all_fixes.sh > fixes1.log 2>&1 &   # 3. resubmit
\end{lstlisting}

That is all.  \cmd{my_list.txt} stands for your own list, e.g.\
\cmd{semimetals_list.txt}: the file of material names that the runs were created
from, one per line.  A name is whatever the material's folder is called ---
a Materials Project ID (\cmd{mp-149}), a formula (\cmd{GaAs}), \cmd{GaAs_PBE}, \dots  The script finds each material's folder
by itself.  When the resubmitted jobs have finished, run step~1 again to check
that everything is now fine.

\begin{notebox}
Run it when your jobs have left the queue.  Materials that still have jobs
queued or running are skipped (shown as \cmd{queued}).
\end{notebox}

\subsection{A worked example}
Without \opt{out}, the output folder is named \cmd{vasp_diagnose_<date>_<time>}, as in this example.

Say you created 300 materials with a high-throughput driver from
\cmd{~/VASP-Flow/semimetals_list.txt}, into the run folder
\cmd{~/VASP-Flow/HT_semimetals/}, and the queue is now empty.

\subsubsection{The list}

The list is the file you already have, for example

\begin{lstlisting}
# ~/VASP-Flow/semimetals_list.txt
mp-149
mp-2534
mp-20351
Bi2Se3
GaAs_PBE
...
\end{lstlisting}

Each name is looked up in the folder that holds the list file, so
\cmd{mp-149} is found as \cmd{~/VASP-Flow/HT_semimetals/materials/mp-149}, and
\cmd{Bi2Se3} as \cmd{~/VASP-Flow/HT_semimetals/materials/Bi2Se3} or as a project folder
\cmd{~/VASP-Flow/Bi2Se3}.  Names must match the folder names exactly
(\cmd{GaAs} does not match \cmd{GaAs_PBE}).  You can also list folder paths, or
mix names and paths (section~\ref{sec:list}).

\subsubsection{Step 1: diagnose}

\begin{lstlisting}[language=bash]
cd ~/VASP-Flow
python3 vasp_diagnose.py semimetals_list.txt
\end{lstlisting}

It prints a summary --- how many materials are fine and how many failed for which reason:

\begin{lstlisting}
Folders checked: 300   (layouts: ht 300)
  ok              262
  oom              14
  scf_nelm          6
  timeout           5
  spilling_high     5
  lobster_fail      4
  nscf_diverged     2
  missing           1
  unknown           1
Fix scripts: 31 to submit, 1 to review (unknown cause)
  review: .../vasp_diagnose_20261012_1530/fix/HT_semimetals__mp-20351.sh
Report : .../vasp_diagnose_20261012_1530/diagnosis.tsv
Submit : nohup bash .../submit_all_fixes.sh > .../submit_all_fixes.log 2>&1 &
\end{lstlisting}

Here 262 materials are fine.  31 failed for a known reason and have a fix script
ready.  One failed for a reason the tool does not recognise; its script is kept
back for you to look at.  5 finished but have a high LOBSTER charge spilling (reported
only), and one name of the list has no folder at all (\cmd{missing}).
Section~\ref{sec:classes} explains each name.

Everything is written into a new folder \cmd{vasp_diagnose_<date>_<time>/}:

\begin{lstlisting}
vasp_diagnose_20261012_1530/
  diagnosis.tsv          the report: one line per material
  fix/<name>.sh          one repair script per failed material
  submit_all_fixes.sh    runs all the repair scripts
\end{lstlisting}

\subsubsection{Step 2: look at the result}

\cmd{diagnosis.tsv} has one line per material: the status of every step and what will be done:

\begin{lstlisting}
label                 ...  steps                                         action
HT_semimetals__mp-149      relax:ok scf:ok bands:ok lobster:ok           ok
HT_semimetals__mp-2534     relax:ok scf:oom bands:not_run lobster:not_run oom -> scf>bands>lobster
HT_semimetals__mp-8062     relax:ok scf:scf_nelm bands:ok lobster:ok     scf_nelm -> scf>bands>lobster
HT_semimetals__mp-20351    relax:unknown scf:ok ...                      REVIEW unknown -> relax>scf>bands>lobster
\end{lstlisting}

Read it with \cmd{bash ht_tools/show_problems.sh vasp_diagnose_20261012_1530}, which lists only the problem lines and what each fix changes (Section~\ref{sec:lookup}), or with \cmd{less -S} or a spreadsheet.
Then open one or two repair scripts to see what they will do, e.g.

\begin{lstlisting}[language=bash]
less vasp_diagnose_20261012_1530/fix/HT_semimetals__mp-2534.sh
\end{lstlisting}

The top of each script says what was found, including the error lines from the logs:

\begin{lstlisting}
# vasp_diagnose fix for HT_semimetals__mp-2534
# folder : /home/me/VASP-Flow/HT_semimetals/materials/mp-2534   (layout: ht)
# diagnosed 2026-10-12 15:30:  relax: ok  scf: oom  bands: not_run  lobster: not_run
#   scf | forrtl: severe (41): insufficient virtual memory
# resubmits: scf -> bands -> lobster
\end{lstlisting}

and further down you see the changes and the submission:

\begin{lstlisting}
set_tag 02_scf/INCAR KPAR 8                 # KPAR was 40
stash 02_scf                                # old outputs -> stale_<date>/02_scf/
...
J_scf=$(sbatch --parsable --job-name=mp-2534_scf --time=00:30:00 --mem=0 job.sbatch scf)
J_bands=$(sbatch ... --dependency=afterok:$J_scf job.sbatch bands)
J_lobster=$(sbatch ... --dependency=afterany:$J_bands job.sbatch lobster)
\end{lstlisting}

You may edit a script before submitting it (another walltime, another KPAR, \dots).

\subsubsection{Step 3: submit}

\begin{lstlisting}[language=bash]
nohup bash vasp_diagnose_20261012_1530/submit_all_fixes.sh > fixes.log 2>&1 &
tail -f fixes.log
\end{lstlisting}

\cmd{fixes.log} shows one block per material:

\begin{lstlisting}
== HT_semimetals__mp-2534
  scf: KPAR 40 -> 8 (40 ranks)
  submitted scf = 4512301 (00:30:00)
  submitted bands = 4512302 (00:30:00)
  submitted lobster = 4512303 (03:00:00)
\end{lstlisting}

\cmd{nohup} lets it keep running after you log out.  It never puts more than 200 of your
jobs in the queue at once (it waits until there is room).  If it is interrupted, start it again: materials it
already submitted are skipped.

\subsubsection{Step 4: check again}

When the queue is empty again, diagnose once more, into a new folder:

\begin{lstlisting}[language=bash]
python3 vasp_diagnose.py semimetals_list.txt --out diagnose_round2
\end{lstlisting}

The repaired materials now show \cmd{ok}.  The ones that failed again get a new
diagnosis and a new script.  Repeat until only \cmd{ok} (and cases you accept,
such as \cmd{spilling_high}) are left.

\subsubsection{Materials held back for review}

Two kinds of scripts are held back: \cmd{unknown} causes, and failures whose usual repair is already
in the INCAR (shown as \cmd{(fix already in INCAR)} --- running the same repair again would fail
the same way).  For these, read the error lines at the top of the script.
Then either repair the run by hand, or let the script run as it is: open
\cmd{submit_all_fixes.sh}, where these scripts appear at the end as commented-out
lines, and remove the \texttt{\#}.  To submit all unknown cases without editing, diagnose again with
\opt{retry-unknown}.

\subsection{Common situations}
\paragraph{Only some runs, or a single project.}  Make a short list with just
those material names, or give a folder:

\begin{lstlisting}[language=bash]
echo GaAs_test > one.txt;  python3 vasp_diagnose.py one.txt
echo HT_semimetals > run.txt; python3 vasp_diagnose.py run.txt   # all materials of that run
\end{lstlisting}

\paragraph{Runs moved to another disk (e.g.\ scratch).}  If a run folder holds a
\cmd{MOVED_TO_SCRATCH.txt} note (written by \cmd{ht_tools/resume_in_scratch.sh}),
its new place is used automatically.  Otherwise tell the script where to look:

\begin{lstlisting}[language=bash]
python3 vasp_diagnose.py semimetals_list.txt --root /scratch/$USER/VASP-Flow
\end{lstlisting}

\paragraph{The same name in two runs.}  If a name is found in more than one run
folder, all copies are checked and a line \cmd{!! GaAs found in 2 runs} is printed.
To check only one of them, put its path in the list instead of the name.

\paragraph{Projects with convergence tests.}  For a project made in two phases
(convergence tests first, then \cmd{submit_calculations.sh} or
\cmd{run_calculations.sh}), broken ENCUT/k-point tests are repaired and
resubmitted; the production steps are \emph{not} started for you, since you choose
their ENCUT and k-mesh from the tests.  Such a project shows
\cmd{phase2_pending} once the tests are complete.

\paragraph{Local projects (no SLURM).}  Their repair script runs VASP directly, one step after
the other.  Run that script on a machine where VASP may run (not on a login node):
\cmd{bash vasp_diagnose_*/fix/projects__GaAs_test.sh}.

\paragraph{Leave a material out.}  \cmd{bash ht_tools/skip_fixes.sh DIAG_DIR NAME ...} comments its line in \cmd{submit_all_fixes.sh} out (\opt{undo} puts it back), e.g.\ for a duplicate that another run replaces.

\paragraph{Fewer jobs in the queue.}
\cmd{MAX_QUEUED=50 nohup bash .../submit_all_fixes.sh > fixes.log 2>&1 &}

\paragraph{Stop submitting.}  \cmd{pkill -f submit_all_fixes.sh}.  Jobs already
submitted keep running; cancel them with \cmd{scancel} if needed.

\paragraph{Undo a repair.}  Nothing is deleted.  Cancel the material's jobs,
move the files from \cmd{<folder>/stale_<date>/<step>/} back into \cmd{<step>/}
and remove the \cmd{TAG = value} lines added at the end of the INCAR.
\cmd{01_relax/POSCAR.orig} is the structure before the first restart.

\paragraph{Problems in the log.}  \texttt{awk '/\textasciicircum !!!|\textasciicircum -{}- /' fixes.log} lists failed
submissions (\cmd{!!!}) and materials skipped because they had jobs in the queue or
their outputs had changed since the diagnosis (\texttt{-{}-}); for the latter, diagnose again.

How the tool decides what failed and what to redo --- options, the list file, the failure classes and their repairs, the outputs and the limitations --- is in Appendix~\ref{app:diagnose}.

\section{Looking up one material or job quickly}
\label{sec:lookup}
% ============================================================

Five short scripts in \cmd{ht_tools/} answer the questions that come up while
checking runs, so that you do not have to remember long \cmd{grep}/\cmd{awk}
commands.  Run them from \cmd{~/VASP-Flow}.  A material can be given by its
name (\cmd{mp-20352}, \cmd{GaAs}) --- it is looked up in
\cmd{/scratch/$USER/VASP-Flow/*/materials/} (and \cmd{~/VASP-Flow/*/materials/},
skipping runs that were moved to scratch) --- or as a folder path.  A name found
in two runs is shown for both.  Started without arguments, each script prints how
to use it.

\begin{tabularx}{\linewidth}{@{}>{\raggedright\arraybackslash}p{0.37\linewidth}X@{}}
\thead
Question & Command \\ \midrule
Which materials failed, and what will each fix change? &
  \cmd{bash ht_tools/show_problems.sh diag_round3} (\opt{all}: also the \cmd{spilling_high} ones) \\
Leave some materials out of the resubmission &
  \cmd{bash ht_tools/skip_fixes.sh diag_round3 NAME ...} (\opt{undo} puts them back) \\
How far did each step of a material get? &
  \cmd{bash ht_tools/show_material_status.sh mp-20352 [relax scf bands dos lobster]} \\

  \cmd{bash ht_tools/show_job_history.sh mp-20352 [mp-6430 ...] [-S 2026-10-01]} \\

\bottomrule
\end{tabularx}

\noindent Only \cmd{skip_fixes.sh} changes a file (it comments lines of
\cmd{submit_all_fixes.sh} in or out); the others only read.

\subsection{A typical checking round}

\begin{lstlisting}[language=bash]
cd ~/VASP-Flow
python3 vasp_diagnose.py ht_list.txt --since 2026-10-01 --out diag_round4
bash ht_tools/show_problems.sh diag_round4               # what failed, what the fixes do
bash ht_tools/show_material_status.sh mp-20352 lobster   # a closer look at one material
bash ht_tools/show_job_log.sh mp-20352 lobster           # ... and at its last log
bash ht_tools/skip_fixes.sh diag_round4 HT_1-500__mp-6430   # do not resubmit this one
nohup bash diag_round4/submit_all_fixes.sh > fixes4.log 2>&1 &
\end{lstlisting}

\subsection{\texttt{show\_problems.sh}: what failed and what the fixes will do}

Prints three blocks: every material of \cmd{diagnosis.tsv} that is not
\cmd{ok} (label, per-step status, planned action); which fix scripts
\cmd{submit_all_fixes.sh} will \cmd{RUN} and which are \cmd{skipped}; and, per fix
script, the changes it makes (e.g.\ \cmd{lobster: nscf_diverged -> ALGO = Fast},
\cmd{scf: walltime 01:00:00}).  Check this before every submission.

\subsection{\texttt{skip\_fixes.sh}: leave materials out}

\begin{lstlisting}[language=bash]
bash ht_tools/skip_fixes.sh diag_round4 HT_1-500__mp-6430 HT_1-500__mp-7889
bash ht_tools/skip_fixes.sh diag_round4 --undo HT_1-500__mp-6430
\end{lstlisting}
Each name is matched as part of the fix script's name, so \cmd{mp-6430} skips the
material in every run.  It prints the new \cmd{RUN}/\cmd{skipped} list.  Typical
uses: a duplicate of a material that another run replaces, or a material whose
result you accept as it is (e.g.\ a relaxation that stops just short of EDIFFG with
tiny forces).

\subsection{\texttt{show\_material\_status.sh}: how far each step got}

For every step folder of the material (or only the steps named):
\begin{itemize}
  \item a header: \cmd{finished} or \cmd{not finished}, and \textbf{how long VASP
        ran} --- the \cmd{Elapsed time} of a finished OUTCAR, or, for an unfinished
        one, the time from VASP's start to the last write of OUTCAR.  This is the
        real running time, not the walltime limit of the job;
  \item the INCAR tags that matter for failures (ALGO, KPAR, NCORE, NBANDS, NELM,
        NSW, EDIFF, EDIFFG, ISYM, ICHARG, ISTART, LDAU);
  \item \textbf{every ionic step} of OSZICAR with the last 5 electronic steps before it;
  \item for the relaxation: converged or not, the last max force and pressure;
  \item when VASP did not finish: when OUTCAR was last written and its last 10 lines,
        which show where VASP stopped (also when it never got to an electronic step).
\end{itemize}

\begin{lstlisting}
== 01_relax (finished, ran 02:13:26)
   ALGO = Normal
   NSW = 100
   EDIFFG = -0.01
   ...
   DAV:   6    -0.310074960321E+02   -0.42113E-05   ...
   DAV:   7    -0.310074982731E+02   -0.15960E-05   ...
   DAV:   8    -0.310074981222E+02    0.15085E-06   ...
    100 F= -.31007498E+02 E0= -.31007498E+02  d E =0.675983E-02   (8 electronic steps)
   relax NOT converged
   FORCES: max atom, RMS     0.032426    0.027855
   external pressure =       -0.12 kB  Pullay stress =        0.00 kB
\end{lstlisting}

\paragraph{Reading OSZICAR.}  Lines starting with \cmd{DAV:} (Davidson),
\cmd{RMM:} (RMM-DIIS) or \cmd{CG:} are \emph{electronic} steps: step number, total
energy, its change dE, the change of the band energies, the number of
$H\psi$ evaluations and the density residual.  A line \cmd{N F= ... E0= ... d E = ...}
closes \emph{ionic} step $N$ (one relaxation or MD step): \cmd{F} is the free
energy, \cmd{E0} the energy extrapolated to zero smearing, \cmd{d E} the change from
the previous ionic step (an MD run adds \cmd{T=} and \cmd{EK=}).  An SCF, bands, DOS
or LOBSTER run has one ionic line at the end.  The status prints the number of
electronic steps of each ionic step; if the run stopped in the middle of one it says
\cmd{... ionic step N still running}.

\subsection{\texttt{show\_job\_history.sh} and \texttt{show\_job\_log.sh}: what SLURM and the logs say}

\cmd{show_job_history.sh} lists, for every job whose name contains one of the
patterns, SLURM's record since \cmd{-S} (default: 3 days ago): job id, name, state
(\cmd{COMPLETED}, \cmd{TIMEOUT}, \cmd{FAILED}, \cmd{OUT_OF_MEMORY}, \cmd{CANCELLED}),
elapsed time, time limit, exit code and end time --- and which of these jobs are in the
queue now.  It shows at a glance whether a step ran out of time, crashed after a minute
(an input or memory problem) or was cancelled.

\cmd{show_job_log.sh} prints the last lines (default 15) of the newest \cmd{.out}
and \cmd{.err} log of one step, or of the job id given.  VASP's own error message is
usually in \cmd{.out}, the crash trace of MPI in \cmd{.err}.

\section{Testing a fix on one material first}
\label{sec:testfix}
% ============================================================

When it is not clear which setting cures a failure, try a few on one material in
short test jobs before changing the production run.  Two scripts make test copies
in \cmd{tests/} of the run folder --- outside \cmd{materials/}, so the production
chain, the diagnosis and the collection scripts never see them.

\begin{lstlisting}[language=bash]
cd /scratch/$USER/VASP-Flow/HT_redo_plainRe
bash ../ht_tools/test_step.sh mp-7889 bands fast    "ALGO=Fast"
bash ../ht_tools/test_step.sh mp-7889 bands kpar4   "KPAR=4; NCORE=2"
bash ../ht_tools/test_step.sh mp-7889 bands ref     ""          # unchanged, for comparison
bash ../ht_tools/test_step.sh --report tests/mp-7889_bands_*    # while they run, and after
\end{lstlisting}

\begin{tabularx}{\linewidth}{@{}>{\raggedright\arraybackslash}p{0.36\linewidth}X@{}}
\thead
Script & What it tests \\ \midrule
\cmd{test_step.sh ID scf|bands|lobster TAG "T=V; ..."} &
  The SCF, bands or LOBSTER NSCF of material \cmd{ID} in \cmd{tests/ID_STEP_TAG/}: the
  step's INCAR and KPOINTS, the material's POTCAR and POSCAR and, for bands/LOBSTER,
  \cmd{02_scf/CHGCAR} (no WAVECAR).  Only VASP runs, not the LOBSTER program. \\
\cmd{test_relax.sh ID TAG "T=V; ..."} &
  The relaxation, from the original input cell, in \cmd{tests/ID_TAG/}. \\
\bottomrule
\end{tabularx}

Each \cmd{TAG=VALUE} replaces that tag in the INCAR (or adds it); \cmd{TAG=} with no
value removes it (\cmd{"NSW=0; IBRION=-1; ISIF="} turns a relax into an SCF).  KPAR is
lowered to a divisor of the core count if needed.  The tests are small and short so
that they start soon: 40 cores and 1~hour by default, changed with
\cmd{T_NTASKS=}, \cmd{T_TIME=}, \cmd{T_PARTITION=} in front of the command.

\opt{report} prints one line per test: status (\cmd{queued}, \cmd{running},
\cmd{ended}, \cmd{finished}, \cmd{timeout}), whether EDIFF was reached, the number of
electronic steps, the first, last and largest $|E|$.  A largest $|E|$ above
${\sim}10^5$~eV means the run diverged.  \cmd{test_relax.sh} \opt{report} gives energy,
volume, pressure and max force per ionic step.

\begin{tipbox}
Once a setting works, put it into production: let \cmd{vasp_diagnose.py} write the
fix (it knows the common ones), or edit the step's INCAR in \cmd{materials/ID/}
yourself and resubmit that step, e.g.\
\cmd{cd materials/ID && sbatch --job-name=ID_bands --time=01:00:00 job.sbatch bands}.
Delete \cmd{tests/} when done.
\end{tipbox}

\section{How the inputs are generated}
\label{app:inputs}
% ============================================================

\subsection{k-mesh formula}
\label{app:kmesh}

\medskip
\textbf{kpra} (k-points per reciprocal atom) $= N_x N_y N_z \times N_\mathrm{atoms}$.
Given a target kpra and the reciprocal lattice vectors $\mathbf{b}_i^*$
(columns of $2\pi(\mathbf{A}^{-1})^\top$), the mesh follows from one formula,
with no search:

\[
  N_i = \mathrm{round}_{2}\bigl(s \, |\mathbf{b}_i^*|\bigr), \qquad
  s = \left(\frac{N_k}{|\mathbf{b}_1^*||\mathbf{b}_2^*||\mathbf{b}_3^*|}\right)^{1/3},
  \quad N_k = \mathrm{kpra}/N_\mathrm{atoms},
\]

where $\mathrm{round}_2$ rounds to the nearest \emph{even} integer (minimum 2),
so that BZ boundary points ($k = 1/2$) are on the mesh.  Because every axis
uses the same $s$, the spacing $|\mathbf{b}_i^*|/N_i$ is the same along all
three axes up to that rounding (a uniform mesh), axes with equal
$|\mathbf{b}_i^*|$ get equal $N_i$, and $N_1N_2N_3N_\mathrm{atoms}\approx$ kpra.
For hexagonal lattices ($a=b$, $\gamma=120^\circ$, detected from the POSCAR)
the two in-plane $N$ are rounded to multiples of 6 ($6,12,18,\dots$) so that
$K$ and $M$ lie on the mesh.  For 2-D slabs the same formula is used in the
plane (square root instead of cube root) and $N_z = 1$, so the in-plane mesh carries the
whole target.  The first line of each generated KPOINTS reports the mesh and
the kpra actually reached.  Any integer may be given instead of
\texttt{coarse}/\texttt{fine} (\texttt{KMESH\_DENSITY: 3000}); the relaxation
has its own density (\texttt{RELAX\_KMESH\_DENSITY}, default coarse).

\subsection{KPAR and NCORE rule}
\label{app:kpar}

When KPAR/NCORE are not specified they are set \emph{per step} from two
numbers only: the total MPI rank count $N$ and that step's irreducible
k-point count $n_k$ (the spglib reduction of the step's own KPOINTS; the
LOBSTER NSCF runs \texttt{ISYM=0}, so its full mesh counts).

\begin{tabularx}{\linewidth}{@{}lX@{}}
\thead
Quantity & Rule \\ \midrule
KPAR & the largest divisor of $N$ that is ${}\le n_k$.  k-point groups scale
  almost perfectly, so use as many as there are k-points; a divisor, so no rank
  is idle. \\
NCORE & the largest divisor of $r = N/\mathrm{KPAR}$ (ranks per k-group) that
  is ${}\le \sqrt{r}$, VASP's own recommendation (NCORE${}=1$ for 1--3 ranks
  per group). \\
\bottomrule
\end{tabularx}

Examples with $N=40$: $n_k \ge 40 \Rightarrow$ KPAR${}=40$, NCORE${}=1$;
$n_k=20 \Rightarrow 20/1$; $n_k=7 \Rightarrow 5/2$; $n_k=1 \Rightarrow 1/5$.
If only one of the pair is given (instruction key, per-step key or an
\texttt{INCAR} block), it is kept --- snapped down to a divisor of $N$ --- and
the other is derived from it: a fixed KPAR gets NCORE from the rule above; a
fixed NCORE gets the largest KPAR${}\le n_k$ that leaves a multiple of NCORE
ranks per group.  Priority, highest first: ELF pin (KPAR${}=1$) $>$
\texttt{INCAR} block $>$ per-step key (\texttt{SCF\_KPAR}, \ldots) $>$ global
\texttt{KPAR}/\texttt{NCORE} $>$ the rule.

Three steps opt out: \textbf{DFPT} is always KPAR${}={}$NCORE${}={}$1 (linear
response supports neither); \textbf{phonons} and \textbf{Wannier90} default to
KPAR${}={}$1 (independent supercell jobs / the Wannier interface), with NCORE
from the rule.  With 40 ranks and the dense meshes of a small cell
(${\le}\,20$ atoms, hundreds of irreducible k-points), KPAR${}=40$,
NCORE${}=1$ is therefore the expected, correct result; it costs one copy of
the wavefunctions per rank, which is small for such cells.

\begin{notebox}
\texttt{LELF=.TRUE.} requires KPAR${}={}$1.  With \texttt{ELF: on} (the
default) the SCF itself runs LELF and is pinned to KPAR${}={}$1.  With
\texttt{ELF: separate} the SCF keeps the automatic KPAR and a short
KPAR${}={}$1 restart writes the ELFCAR afterwards
(Section~\ref{sec:elf-separate}).  Convergence tests drop \texttt{LELF}
automatically.
\end{notebox}

\subsection{Eigensolver (ALGO) of each step}
\label{app:algo}

Relaxation and SCF use \cmd{ALGO = Normal} (blocked Davidson), the robust choice
while the density still changes.  The fixed-density steps --- bands, DOS and the
LOBSTER NSCF (\cmd{ICHARG = 11}) --- use \cmd{ALGO = Fast}: a few Davidson steps,
then RMM-DIIS.  With the density fixed, pure Davidson ran away to
$|E|\sim10^{10}$~eV for Ba$_2$YReO$_6$ and Sr$_2$YReO$_6$ (independent of KPAR/NCORE);
\cmd{ALGO = Fast} converged in 20 steps and \cmd{ALGO = VeryFast} (RMM-DIIS only)
also converged, while \cmd{ALGO = All} (conjugate gradients) is not allowed with
\cmd{ICHARG = 11} and stops VASP.  A functional's own ALGO (HSE06: \cmd{Damped}) and
any INCAR block win over these defaults.  \cmd{vasp_diagnose.py} repairs a diverged or
unconverged fixed-density step along \cmd{Normal} $\to$ \cmd{Fast} $\to$ \cmd{VeryFast},
and a non-converging SCF with \cmd{ALGO = All}.

\subsection{LOBSTER k-mesh and memory}
\label{app:lobster-mem}

The LOBSTER NSCF must run without symmetry (\cmd{ISYM = 0}), so VASP keeps every
k-point of the mesh; only time reversal pairs $\mathbf k$ with $-\mathbf k$:
\[
  N_\mathrm{k} = \frac{N_1N_2N_3 - t}{2} + t,\qquad t = 2^{\,\#\{i:\ N_i\ \mathrm{even}\}}
\]
(6916 for 24$\times$24$\times$24, 2820 for 16$\times$16$\times$22, as VASP reports).
Its memory grows with $N_\mathrm{k}\times N_\mathrm{PW}$, where the plane waves per
k-point follow from the cell volume and the cutoff,
$N_\mathrm{PW} = V k_c^3/(6\pi^2)$ with $k_c = \sqrt{\mathrm{ENCUT}/3.81~\mathrm{eV\,\AA^2}}$.
Two runs with $N_\mathrm{k}N_\mathrm{PW} = 1.5\times10^7$ and $1.8\times10^7$ stopped at
set-up with \cmd{insufficient virtual memory}, on two 96-core nodes as well as on one
40-core node with 375~GB --- more memory per rank did not help, a smaller mesh does.
The generators therefore start from the SCF mesh and, if it has more than
\cmd{LOBSTER_MAX_KPTS} points ($N_1N_2N_3$, default 10000) or
$N_\mathrm{k}N_\mathrm{PW} > $ \cmd{LOBSTER_MAX_KPW} (default $6\times10^6$), scale all $N_i$
by the same factor (even, at least 2; $N_z = 1$ for slabs; in-plane multiples of 6 for
hexagonal cells) until both hold.  The point limit alone would not be enough:
16$\times$16$\times$22 has only 5632 points but failed, because that cell has twice as
many plane waves per k-point.  The KPOINTS comment then reads e.g.\
\cmd{reduced from 24x24x24: 2052 k x ~2822 PW}.  The KPAR rule uses the reduced
count.  Set either limit to 0 (\cmd{LOBSTER_MAX_KPTS: 0}, \opt{lobster-max-kpw 0}) to
switch it off, or a larger \cmd{LOBSTER_MAX_KPW} on nodes with more memory.  For COHP/ICOHP integrals a mesh of a few
hundred to two thousand k-points is ample for cells of up to $\sim$20 atoms.

\subsection{Relaxation $\to$ SCF hand-off}
\label{sec:handoff}

The relaxation starts from scratch (\texttt{ISTART = 0}, \texttt{ICHARG = 2})
and writes \texttt{WAVECAR} and \texttt{CHGCAR}.  \texttt{02\_scf/copy\_from\_relax.sh}
copies the relaxed geometry and the CHGCAR; if the SCF k-mesh, spin and cutoff
equal the relaxation's it also copies the WAVECAR and the SCF starts from both
(\texttt{ISTART = 1}, \texttt{ICHARG = 1}), otherwise it starts from the CHGCAR
alone (\texttt{ISTART = 0}, \texttt{ICHARG = 1}) because wavefunctions on
different k-meshes are not interchangeable.  The decision is made at run time,
so k-meshes edited or patched after generation are handled.  Putting
\texttt{ISTART} or \texttt{ICHARG} in an \texttt{INCAR scf:} block disables the
mechanism.

\subsection{Band-path detection}
\label{app:kpath}

Since v1.6 the generator first determines the \emph{actual space group}
of the POSCAR with spglib (via pymatgen's
\texttt{KPathSetyawanCurtarolo}) and uses the standard
Setyawan--Curtarolo high-symmetry path for that space group.  Every
high-symmetry point is transformed through Cartesian reciprocal space
into the reciprocal basis of \emph{this} POSCAR, so the path is correct
for the actual cell used in the SCF regardless of orientation or
setting.

If spglib or pymatgen is not installed (or the symmetry analysis
fails), the generator falls back to the geometric classifier below: it
reads the POSCAR lattice vectors, computes cell lengths and angles, and
selects a default path by Bravais type.  2-D structures always use the
geometric route so the in-plane path is preserved.

\subsection{Two-step ELF (\texttt{ELF: separate})}
\label{sec:elf-separate}

\texttt{LELF} only works with KPAR${}={}$1, which removes the k-point
parallelism that makes an SCF on a small cell fast.  With
\begin{lstlisting}
ELF: separate        # or  ELF: two-step
\end{lstlisting}
the ELF is produced in two steps inside \texttt{02\_scf}, in the same job:
\begin{enumerate}
\item The SCF runs normally --- automatic KPAR/NCORE, no \texttt{LELF},
  \texttt{LWAVE}/\texttt{LCHARG=.TRUE.}.
\item \texttt{run\_elf.sh} (called by \texttt{run.sh} after VASP) copies the
  converged \texttt{WAVECAR}, \texttt{CHGCAR}, \texttt{POSCAR},
  \texttt{KPOINTS} and \texttt{POTCAR} into \texttt{02\_scf/elf/} and runs
  VASP there with \texttt{02\_scf/elf/INCAR}: the SCF INCAR (same ENCUT,
  smearing, MAGMOM, $+U$, user overrides) plus \texttt{ISTART=1},
  \texttt{ICHARG=1}, \texttt{LELF=.TRUE.}, \texttt{LWAVE}/\texttt{LCHARG=.FALSE.},
  KPAR${}={}$1 and NCORE from the rule for one k-group.  \texttt{NBANDS} is
  set at run time to the value the SCF used (read from its \texttt{OUTCAR}),
  so the WAVECAR is read as is.  Starting from converged wavefunctions, this
  restart needs only a few electronic steps.
\item \texttt{ELFCAR} is copied back to \texttt{02\_scf/ELFCAR}, where
  \texttt{analyze.sh}, \texttt{elf\_bonds.py} and the GUI look for it; the
  copied WAVECAR/CHGCAR in \texttt{elf/} are deleted.
\end{enumerate}
If the SCF left no WAVECAR/CHGCAR, the ELF pass is skipped with a message.
The DOS, bands and LOBSTER steps still read \texttt{02\_scf/CHGCAR}, which the
ELF pass does not touch.  \texttt{ht-mp-scf.py} uses this mode by default;
write \texttt{ELF: on} in \texttt{instructions.txt} for the old single run.

\subsection{Convergence tests: test structure and parameter choice}
\label{app:conv}

\subsubsection{Shifted test structure}

The POSCAR used in \texttt{00\_convergence} has \textbf{atom 1 displaced
by $(0.01,\,0.02,\,0.03)$\,\AA{} (Cartesian)} so that the force on it is
non-zero and its convergence can be tracked --- at the equilibrium
(high-symmetry) positions the forces would vanish identically and the
force panel would be meaningless.  The displacement is converted through
the lattice for Direct-mode POSCARs.  All production steps
(\texttt{01\_relax}, \texttt{02\_scf}, \dots) use the \emph{original,
unshifted} positions.

\subsubsection{Automatic parameter selection}

After the runs, \texttt{00\_convergence/choose\_params.py} (invoked by
\texttt{run\_convergence.sh}, \texttt{analyze\_convergence.sh}, and the
phase-2 scripts) selects the smallest ENCUT and k-mesh from which every
subsequent change stays below
\[
  \max_i \bigl|\Delta F_i^{\text{atom 1}}\bigr| < 5~\text{meV/\AA}
  \quad\text{and}\quad
  \max_i \bigl|\Delta \sigma_{ii}\bigr| < 0.5~\text{kbar},
\]
and writes the result to \texttt{00\_convergence/converged\_params.txt}.
Phase 2 (\texttt{run\_calculations.sh}, \texttt{submit\_calculations.sh},
and the GUI form) offers these values as defaults; when run
\emph{non-interactively} --- e.g.\ a convergence test automatically
followed by the SCF in a chained/nohup run --- they are applied without
prompting.  If the criteria are not met within the tested range, the
largest tested value is used and a \texttt{NOT CONVERGED} warning is
issued.  Thresholds can be overridden:
\texttt{choose\_params.py --ftol 3 --ptol 0.2}.

\subsection{DFPT: fixed parallel and symmetry settings}
\label{app:dfpt}

\begin{notebox}
Both routes support neither k-point nor band parallelisation:
\textbf{KPAR and NCORE are forced to 1} in the generated INCAR
(overriding any global or per-step setting).  The full MPI task count
is still used for plane-wave parallelisation.
Likewise \textbf{ISYM=2 is enforced} (symmetry imposed): perturbation
theory relies on the symmetry-reduced perturbation set, so a
symmetry-off \texttt{ISYM=0}/\texttt{$-$1} --- e.g.\ from a global
\texttt{INCAR:} override block intended for the LOBSTER/NSCF steps ---
is never inherited by \texttt{06\_dfpt}.
\end{notebox}

\texttt{copy\_from\_scf.sh} (invoked by \texttt{run.sh}) pulls
\texttt{WAVECAR} and \texttt{CHGCAR} from \texttt{02\_scf} at run time.
If \texttt{02\_scf} has been converted in place for LOBSTER
(\texttt{ISYM=0}/\texttt{$-$1} in its INCAR, as done by the
high-throughput \texttt{run\_scf\_for\_lobster.sh}), the
\texttt{WAVECAR} copy is skipped --- it holds the full, unsymmetrised
k-mesh, which the ISYM=2 run cannot restart from --- and VASP
regenerates the orbitals from the \texttt{CHGCAR}, which the LOBSTER
conversion (a fixed-charge NSCF with \texttt{LCHARG=.FALSE.}) leaves
untouched.  If the symmetry-off INCAR is \emph{not} a fixed-charge
NSCF, a warning is printed that the \texttt{CHGCAR} itself may stem
from a symmetry-off SCF and a symmetric SCF should be re-run first.

\subsection{LOBSTER projected DOS vs.\ the VASP DOS}
\label{app:lobster-dos}

The LOBSTER card also carries a projected-DOS plot
(\texttt{analysis/*\_lobster\_dos.\{png,pdf\}}, generated by every interface
but displayed only in the GUI), drawn in the same cumulative-stacked layout as
the \texttt{04\_dos} projected DOS.  It answers a question the two DOS files
raise on their own.

VASP's \texttt{LORBIT=11} PDOS projects onto spherical harmonics \emph{inside
the PAW augmentation spheres}, which do not fill space, so the interstitial
charge is unassigned and $\sum \mathrm{PDOS} < $ total DOS --- severely so for
free-electron-like metals (only 25\% of the electrons for fcc Al; 72\% for
MoSe\textsubscript{2}, whose Mo-$d$ and Se-$p$ states are compact).  LOBSTER
instead re-expands the PAW states in a local atomic-orbital basis and performs
a Mulliken population analysis, so its decomposition is complete by
construction: the stacked areas sum \emph{exactly} to LOBSTER's own total.

The plot therefore shows three things: the stacked LOBSTER channels, LOBSTER's
total (dashed grey, identically the top of the stack), and the projection-free
VASP total from \texttt{04\_dos} (solid black).  The gap between the last two
is the charge spilling, reported in \texttt{lobsterout} and typically 1--4\%.
For the \emph{total} DOS the VASP curve is the reference --- it is a direct
eigenvalue count under the tetrahedron method, with no projection at all --
whereas for \emph{orbital-resolved} weights the LOBSTER decomposition is the
more complete one, and is the same basis that produces the COHP/COBI curves.
Note that the two curves also carry different broadening (\texttt{04\_dos} uses
\texttt{ISMEAR=-5}; the LOBSTER NSCF is forced to Gaussian smearing, and
LOBSTER applies its own \texttt{gaussianSmearingWidth} on a coarser energy
grid), so some of the visible difference is resolution rather than physics.
Both smearing settings are stated in the plot legend.

\section{How SLURM steps continue past the time limit}
\label{sec:slurm-continue}
% ============================================================

\textbf{A step that reaches its limit is continued, not lost.}  Every step
script asks SLURM for a warning 15~min before the limit
(\texttt{-{}-signal=B:USR1@900}).  On the warning it writes a
\texttt{STOPCAR} (\texttt{LSTOP} for a relaxation: stop after the current
ionic step; \texttt{LABORT} otherwise), lets VASP finish cleanly and requeues
the job with \texttt{scontrol requeue} --- same job id, so jobs chained after
it with \texttt{afterok} keep waiting.  The requeued job then
\begin{itemize}
  \item \textbf{relaxation}: continues from the \texttt{CONTCAR} (or, if that
    is empty, from the last \texttt{XDATCAR} frame, cell included);
  \item \textbf{LOBSTER}: skips the NSCF if it had finished and reruns only
    the LOBSTER binary;
  \item other steps: rerun.
\end{itemize}
The interrupted \texttt{OUTCAR}/\texttt{XDATCAR} are kept as
\texttt{*.timeout0}, \texttt{*.timeout1}, \ldots  If requeueing is not
allowed on the cluster, the job resubmits a copy of itself with the same
name and time limit and re-points dependent jobs to it.  At most
\texttt{VF\_MAX\_RESTARTS} (default 5) continuations per step.

\subsection{\texttt{ht-semimetals.py} in detail}
\label{sec:ht-semimetals}

It builds a self-contained \texttt{highthroughput\_*} directory: one
\texttt{materials/<id>/job.sbatch} per material; \texttt{submit\_all.sh}
submits it once per step (\texttt{relax}, \texttt{scf}, \texttt{bands},
\texttt{lobster}) as an \texttt{afterok} chain with the walltimes
\texttt{TIME\_RELAX}/\texttt{TIME\_SCF}/\texttt{TIME\_BANDS}/\texttt{TIME\_LOBSTER}
of \texttt{env.sh}, and steps that reach their limit continue automatically
(Section~\ref{sec:slurm-time}).  The steps are the relaxation
(\texttt{01\_relax}, IBRION = 1, ISIF = 3, same k-density as the SCF; if the
first pass does not reach the force criterion it is restarted once from its
CONTCAR), the SCF from the relaxed structure, bands and the LOBSTER NSCF +
LOBSTER (finished steps are skipped on resubmission); the LOBSTER job ends and ends with \texttt{analyze.sh} (plots and
\texttt{lobster\_summary.csv} in \texttt{analysis/}).  ENCUT and the LOBSTER
NBANDS come from the POTCARs at generation time and are checked against
\texttt{potcar\_manifest.json} when the POTCARs are built on the cluster.
POTCAR variants follow the Materials Project choices by default
(\texttt{-{}-potcar-set mp}: e.g.\ Re\_pv, Ti\_pv, Ga\_d, Li\_sv, taken from
pymatgen's \texttt{MPRelaxSet}); the older ``plain element first'' rule
(\texttt{-{}-potcar-set minimal}) gave minimal-valence POTCARs, and
Ba$_2$YReO$_6$/Sr$_2$YReO$_6$ with plain Re collapsed into an unphysical state.
Relax, SCF and bands use the same \texttt{NBANDS} $= 1.2\times$ VASP's default
(from NELECT, NIONS and the starting moment; rounded up to even): VASP's default
leaves too few empty bands for narrow d bands, the electron count then drifts
between SCF steps (\texttt{BRMIX: very serious problems}) and the SCF diverges.
The bands step never uses fewer bands than its SCF.  The k-point density is
\opt{kpra} (default 8000 k-points per reciprocal atom), the same spacing along all
axes.  The LOBSTER NSCF uses the SCF mesh, reduced when it exceeds
\opt{lobster-max-kpts} or \opt{lobster-max-kpw} (Appendix~\ref{app:lobster-mem}).  Every
job requests the whole node's memory (\texttt{\#SBATCH -{}-mem=0}).  \opt{kspacing} is
an alternative to \opt{kpra}; before v2.5 it was the default (0.10~\AA$^{-1}$, very
dense: 24$\times$24$\times$24 for the 8-atom Sc$_2$Al$_2$C$_2$O$_2$, 110592~kpra).
3d elements (V--Ni) start spin-polarised.  GGA+U follows the default rule
(only chalcogenides/halides, Section~\ref{sec:ggau}) unless
\texttt{-{}-gga\_u on|off} is given.  There is no DFPT step (dielectric
tensors and Born charges are ill-defined at zero gap, and the linear-response
loop tends not to converge) and no ELF (\texttt{ELF: off}).

\section{How \texttt{vasp\_diagnose.py} works}
\label{app:diagnose}
% ============================================================

\subsection{Command line}

\begin{lstlisting}[language=bash]
python3 vasp_diagnose.py LIST [options]
\end{lstlisting}

\begin{center}
\begin{tabularx}{\linewidth}{l l >{\raggedright\arraybackslash}X}
\toprule
\thead Option & Default & Meaning \\
\midrule
\opt{out DIR}       & \cmd{vasp_diagnose_<date>_<time>} & folder for the report and the scripts \\
\opt{root DIR}      & --- & another folder to look up material names in (can be repeated) \\
\opt{since DATE}    & 14 days ago & how far back SLURM's job records (\cmd{sacct}) are read, YYYY-MM-DD;
                                    must reach back to the jobs being diagnosed \\
\opt{kpar-max N}    & 8 & largest KPAR written by the out-of-memory repair \\
\opt{spill-max X}   & 5 & LOBSTER charge spilling (\%) above which a material is flagged \\
\opt{retry-unknown} & off & also submit the materials whose failure was not recognised \\
\opt{max-queued N}  & 200 & default queue limit of \cmd{submit_all_fixes.sh}
                            (override later with \cmd{MAX_QUEUED=}) \\
\bottomrule
\end{tabularx}
\end{center}

It needs only Python~$\geq$~3.6 (no extra packages) and uses \cmd{sacct} and
\cmd{squeue} when they exist.

\subsection{The list file}\label{sec:list}

One entry per line; empty lines, \texttt{\#} comments and anything after the first word are ignored.
An entry is

\begin{center}
\begin{tabularx}{\linewidth}{l >{\raggedright\arraybackslash}X}
\toprule
\thead Entry & Checked \\
\midrule
a \textbf{material name} --- any folder name: \cmd{mp-149}, \cmd{GaAs}, \cmd{Bi2Se3_soc}, \dots &
  the folders of that name in \emph{R}, \emph{R}\cmd{/*/} or \emph{R}\cmd{/*/materials/},
  where \emph{R} is the folder holding the list file, and each \opt{root} \\
a \textbf{material or project folder} (has \cmd{00_convergence}, \cmd{01_relax}, \dots) & that folder \\
a \textbf{run folder} with \cmd{materials/} & every material in \cmd{materials/};
  if the run has a \cmd{material_list.txt}, only the materials in it (other folders are named and skipped) \\
any \textbf{other folder} & every sub-folder that is a material/project folder \\
\bottomrule
\end{tabularx}
\end{center}

A word that is a folder (relative to the list file's folder) is taken as a path;
otherwise it is a material name.  Names are matched exactly, so \cmd{GaAs} finds
\cmd{.../GaAs} but not \cmd{.../GaAs_PBE}, and a name may contain any characters a
folder name can.  A name that is found nowhere is reported as \cmd{missing}.

\subsection{Kinds of runs}

How the jobs are resubmitted depends on how the run was made:

\begin{center}
\begin{tabularx}{\linewidth}{l >{\raggedright\arraybackslash}X >{\raggedright\arraybackslash}X}
\toprule
\thead Layout & Recognised by & Resubmitted with \\
\midrule
\cmd{ht} & \cmd{job.sbatch} in the material folder (high-throughput drivers) &
  \cmd{sbatch job.sbatch <step>}, walltimes from \cmd{TIME_*} in the run's \cmd{env.sh};
  steps relax, scf, bands, lobster \\
\cmd{slurm} & \cmd{run.sh} files with \texttt{\#SBATCH} lines (\cmd{vasp-agent-slurm.py}) &
  \cmd{sbatch <step>/run.sh}, with its job name and walltime \\
\cmd{local} & anything else (\cmd{vasp-agent.py}) &
  \cmd{(cd <step> && bash run.sh)}, in the foreground \\
\bottomrule
\end{tabularx}
\end{center}

Each material gets a \emph{label}, \cmd{<run folder>__<material>}
(e.g.\ \cmd{HT_semimetals__mp-149}, \cmd{projects__GaAs_test}); it names the
repair script and the report line.

\subsection{When is a step OK?}

\begin{center}
\begin{tabularx}{\linewidth}{l >{\raggedright\arraybackslash}X}
\toprule
\thead Step & OK when \\
\midrule
\cmd{00_convergence} & every point of the ENCUT test (\cmd{encut/encut_<E>/}) and of the k-point test
  (\cmd{kpoints/<N1>x<N2>x<N3>/}) that its \cmd{run.sh} will make has finished with a converged SCF.
  If \cmd{converged_params.txt} says a quantity did not converge in the tested range, this is
  noted in the report (widen the range yourself) \\
\cmd{01_relax}  & OUTCAR has \cmd{reached required accuracy} \\
\cmd{02_scf}    & OUTCAR finished (\cmd{General timing and accounting}) and the SCF converged
                  (\cmd{aborting loop because EDIFF is reached}) \\
\cmd{03_bands}  & finished, converged, and no energy above $10^6$~eV in OSZICAR \\
\cmd{04_dos}    & as bands, and a non-empty DOSCAR \\
\cmd{06_dfpt}   & finished with Born charges or the dielectric tensor in OUTCAR \\
\cmd{08_lobster}& \cmd{lobster.out} has \cmd{finished in}; a charge spilling above
                  \opt{spill-max} is reported but counts as OK \\
\bottomrule
\end{tabularx}
\end{center}

\cmd{05_wannier} and \cmd{07_phonons} are not checked (noted as \cmd{unchecked}).

For a step that is not OK, the cause is read from the step's newest SLURM logs,
\cmd{vasp.out}, the end of OUTCAR and the SLURM job record (state, run time,
time limit).  The job record wins: a job SLURM ended for its time limit is a
\cmd{timeout}, whatever else is in the logs.  So is a VASP run stopped by the STOPCAR
that the VASP-Flow scripts write shortly before the time limit (\cmd{hard stop encountered},
\cmd{soft stop encountered}).  Messages after which VASP carries on, such as
\cmd{Sub-Space-Matrix is not hermitian} or \cmd{The number of bands has changed}, are
shown in the script header but never taken as the cause.

\subsection{Failure causes and their repairs}\label{sec:classes}

\renewcommand{\arraystretch}{1.05}
\begin{center}
\footnotesize
\begin{tabularx}{\linewidth}{>{\ttfamily}l >{\raggedright\arraybackslash}X >{\raggedright\arraybackslash}X}
\toprule
\thead \normalfont Name & Meaning & Repair \\
\midrule
oom & out of memory (\cmd{insufficient virtual memory}, \cmd{Cannot allocate memory},
  killed by the OOM handler, MPI time-outs between nodes) &
  KPAR lowered to at most \opt{kpar-max} (a divisor of the MPI ranks); all node memory requested;
  for the LOBSTER NSCF also its k-mesh halved per axis \\
timeout & the job hit its time limit & walltime doubled; a relax continues from its last structure \\
scf\_nelm & SCF stopped at NELM without converging & \cmd{ALGO = All}, \cmd{NELM} $\geq 150$ \\
nscf\_diverged & bands/DOS/LOBSTER energies exploded & 30\% more bands than the SCF (not for LOBSTER);
  eigensolver \cmd{Normal} (Davidson, VASP's default) $\to$ \cmd{Fast} $\to$ \cmd{VeryFast} (RMM-DIIS), then held;
  \cmd{NELM} $\geq 150$ \\
nscf\_unconv & bands/DOS stopped at NELM & \cmd{ALGO} as for nscf\_diverged, \cmd{NELM} $\geq 150$ \\
relax\_unconv & relax ended without reaching the force criterion & continues from CONTCAR (or the last XDATCAR frame) \\
zbrent & \cmd{ZBRENT: fatal error} in a relax & \cmd{IBRION} 2 $\to$ 1, continue \\
symmetry & VASP symmetry errors & \cmd{SYMPREC = 1E-4} (\cmd{ISYM = 0} if SYMPREC was set) \\
edddav & \cmd{EDDDAV}/\cmd{ZHEGV} errors & SCF: \cmd{ALGO = All}; relax: \cmd{ALGO = Normal}, if that fails again \cmd{ALGO = All}; bands etc.: as nscf\_diverged \\
wavecar & WAVECAR does not fit the new run & WAVECAR moved aside, start from CHGCAR \\
chgcar & CHGCAR unreadable or cut off & SCF started from scratch (\cmd{ICHARG = 2}) \\
chgcar\_missing & a later step needs \cmd{02_scf/CHGCAR}, which is missing or cut off & SCF redone first \\
lobster\_fail & VASP part of the LOBSTER step finished, the LOBSTER program did not & only the LOBSTER program is rerun \\
quota & disk full / quota exceeded & resubmitted unchanged --- \textbf{free space first} \\
mpi\_init & MPI failed to start (bad node) & resubmitted unchanged \\
not\_run & never ran (e.g.\ an earlier step failed) & submitted \\
unknown & none of the above & script written but held back for review \\
\emph{(any)} \dots\ \cmd{(fix already in INCAR)} & the repair for this cause is already in the INCAR, so it did not help &
  script written but held back for review \\
\midrule
spilling\_high & LOBSTER finished, spilling $>$ \opt{spill-max} & none (report only) \\
missing & a listed name has no folder & none (report only) \\
phase2\_pending & convergence tests done, production steps not started & none: start them with
  \cmd{submit_calculations.sh} / \cmd{run_calculations.sh} \\
queued & the material still has jobs in the queue & none: diagnose later \\
\bottomrule
\end{tabularx}
\end{center}
\renewcommand{\arraystretch}{1.0}

A material is counted under the cause of its \emph{first} failed step.
A charge spilling is a property of the LOBSTER basis set, so rerunning does not
change it; lowering it needs other basis functions in \cmd{lobsterin}.

\subsection{What is redone}

\begin{itemize}
  \item If the relax or the SCF failed, that step and \emph{all} later steps are redone.
  \item Otherwise only the failed later steps (bands, DOS, DFPT, LOBSTER).  If they need
        \cmd{02_scf/CHGCAR} and it is missing or cut off, the SCF is redone first.
  \item \textbf{Convergence tests} are repaired on their own: only the broken points
        are moved aside, the fix of their cause goes into the test's INCAR, and the test's
        \cmd{run.sh} is resubmitted --- it skips the points that are already done.
        Production steps are not redone because of a convergence test.
  \item \textbf{LOBSTER only}: when the VASP part of the LOBSTER step finished and its
        WAVECAR is there, only the LOBSTER program reruns (not for local projects).
  \item In high-throughput runs \cmd{job.sbatch} cannot run DOS or DFPT; such steps are
        reported (\cmd{job.sbatch cannot run: dos}) but not resubmitted.
\end{itemize}

What a repair script changes in a material folder:

\begin{itemize}
  \item \textbf{INCAR}: every line of a changed tag is removed and \cmd{TAG = value} is
        added at the end.  No other tags are touched.
  \item \textbf{Old outputs} of every redone step (OUTCAR, OSZICAR, CHGCAR, WAVECAR,
        \cmd{*.lobster}, \dots, or the whole broken convergence point) are moved to
        \cmd{<folder>/stale_<date>/}.  Inputs stay in place; nothing is deleted.
  \item \textbf{Relax restarts} from the newest complete CONTCAR (else the last XDATCAR frame);
        the original POSCAR is kept once as \cmd{POSCAR.orig}.
  \item \textbf{SCF start}: if the relax's CHGCAR is cut off, the SCF starts from scratch.
\end{itemize}

\subsection{Order of the resubmitted jobs}

\begin{center}
\begin{tabularx}{\linewidth}{l >{\raggedright\arraybackslash}X}
\toprule
\thead Layout & Order \\
\midrule
\cmd{ht} & each step waits for the previous one to succeed (\cmd{afterok}); LOBSTER after
  bands waits only for it to end (\cmd{afterany}), as it does not need the bands \\
\cmd{slurm} & SCF waits for the relax; bands, DOS, DFPT and LOBSTER wait for the SCF \\
\cmd{local} & one after the other; stops at the first failure \\
\bottomrule
\end{tabularx}
\end{center}

Convergence tests are submitted without waiting for anything.  Walltimes are the
run's own (\cmd{env.sh}, \texttt{\#SBATCH -{}-time}, or relax 8\,h, SCF 4\,h, bands/DOS 2\,h,
DFPT 8\,h, LOBSTER 4\,h, tests 8\,h), doubled after a time-out.

\subsection{Output files}

\paragraph{\cmd{diagnosis.tsv}} --- tab-separated, one line per material:

\begin{center}
\begin{tabularx}{\linewidth}{l >{\raggedright\arraybackslash}X}
\toprule
\thead Column & Content \\
\midrule
\cmd{label}  & the material's label \\
\cmd{layout} & \cmd{ht}, \cmd{slurm}, \cmd{local} (\cmd{-} for a missing name) \\
\cmd{path}   & its folder \\
\cmd{steps}  & \cmd{step:status} for each step (\cmd{conv:encut}, \cmd{conv:kpoints}, \cmd{relax}, \dots) and notes \\
\cmd{action} & \cmd{ok}, a report-only name, or \cmd{<cause> -> <steps redone>}; \cmd{REVIEW} in front when held back \\
\cmd{script} & its repair script, if any \\
\bottomrule
\end{tabularx}
\end{center}

\begin{lstlisting}[language=bash]
awk -F'\t' 'NR>1 {split($5,a," "); n[a[1]]++} END {for (k in n) print k, n[k]}' diagnosis.tsv
awk -F'\t' '$5 ~ /^REVIEW/ {print $1}' diagnosis.tsv
\end{lstlisting}

\paragraph{\cmd{fix/<label>.sh}} --- a stand-alone bash script; it can be run on its own.
In order it:
\begin{enumerate}
  \item records the diagnosis and the error lines in its header;
  \item \textbf{stops} if the material has jobs in the queue, or if any of its OUTCARs
        or \cmd{lobster.out} changed since the diagnosis (so it is safe to run late, or twice);
  \item applies the INCAR changes and moves the old outputs aside;
  \item submits the jobs (or runs them, for a local project);
  \item leaves a marker \cmd{.submitted/<label>} in the output folder.
\end{enumerate}

\paragraph{\cmd{submit_all_fixes.sh}} --- runs every repair script in turn; skips those
with a \cmd{.submitted} marker; waits while you have \cmd{MAX_QUEUED} or more jobs
in the queue (all your jobs count); lists the held-back \cmd{unknown} scripts at the end
as commented-out lines.

\subsection{Limitations}

\begin{itemize}
  \item Jobs are recognised by their job names (\cmd{<material>_<step>}, or the name in
        the step's \cmd{run.sh}).  Jobs submitted under other names are not seen, and a failure
        cause is then taken from the log files only.
  \item Only jobs since \opt{since} are known to the tool.  Without a job record a time-out is
        still recognised from the log, but the walltime is doubled from the configured value.
  \item A second out-of-memory failure with KPAR already $\leq$ \opt{kpar-max} is resubmitted
        with the same KPAR (the LOBSTER mesh is halved again); diagnose again with a smaller
        \opt{kpar-max}.
  \item A material that fails again with the same cause after one repair (e.g.\
        \cmd{scf_nelm}) needs a look by hand.
  \item \cmd{quota} and \cmd{mpi_init} are resubmitted unchanged: free disk space first;
        node failures are usually transient.
  \item \cmd{05_wannier} and \cmd{07_phonons} are not checked; a convergence-test range that
        was too small is reported but not widened.
  \item Two runs holding the same material use the same job names (\cmd{<material>_<step>}), so a job of one
        makes the material show as \cmd{queued} in both.
  \item Repair scripts use GNU \cmd{sed} and \cmd{stat}: they are meant for Linux clusters.
\end{itemize}
